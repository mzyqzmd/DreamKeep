# 遗物可实现清单

> 依据 `Doc/_遗物系统总览.md`（STS2 全 289 件）与本项目现有机制逐件判定。
> 约束：**不新增状态类型（SO_Perk/BP_*）与词条类型（AffixData/CA_*）**；遗物效果 =「订阅既有 `BE_*` 事件 + 构造既有 `BA_*` 动作 / 既有升级与牌堆操作」的组合。
> 判定口径（用户拍板）：只收**现有机制逐字复刻**的遗物；近似替代（活力→力量等）与管线改造类不进主清单。

## 1. 框架对接说明（遗物效果怎么写）

- **效果类**：每件遗物一个 `RelicEffect` 子类（GameRun 程序集），构造时 `Dispatcher.Register<BE_xxx>(handler)` 订阅，触发时 `PerformAsync(new BA_Xxx(...))`（入队 `ActionSystem` + 排空等待）。
- **配置资产**：每件遗物一个 `SO_Relic` 子类（`SO_*`，ConfigData 程序集，`[CreateAssetMenu]` 建资产），效果数值直接配在子类上、Inspector 可调；装配期由 `RelicBaker` 按资产类型分派。
- **运行时数据**：`Player.Relics` 持有 `RuntimeRelic`（RuntimeData 程序集），一局一份，将来的局面状态（计数、次数耗尽）住本类；装配期由 `RelicBaker` 逐件烘出效果。
- **处理器形态**：事件分两类——
  - **直发型**（阶段代码直接 `PlayEvent`，不经动作系统）：`BE_BattleStarted`、`BE_TurnStarted`、`BE_PlayerTurnActiveStarted`、`BE_PlayerTurnEnded`、`BE_BattleEnded`。处理器内 `PerformAsync` 会立即排空（此时队列空闲），动作演出被完整等待在事件分派链内；
  - **排空内型**（由某动作 `Execute` 产出、正在 `PerformAllAsync` 循环中播放）：`BE_CardPlayed`、`BE_DamageDealt`、`BE_ActorDied`、`BE_DiscardReshuffled` 等。处理器内 `PerformAsync` 命中排空守卫直接返回，动作由当前轮循环继续出队（`ActionSystem` 注释背书），演出保持串行。
- **战斗域两处一行级改动**（装配必需，行为等价）：
  1. `BattleLoop.ActionSystem` `internal → public`（GameRun 装配链要把执行引擎交给遗物效果）；
  2. `BattleEventDispatcher.DispatchAsync` 的复用容器 `_waits` 改为方法内局部列表（处理器在分派链内嵌套播放新事件时，复用字段会被嵌套分派 `Clear` 污染外层并行等待）。
- **触发落点与回合时序**（已查证）：
  - `BP_PlayerTurnStart`：`BE_TurnStarted`（直发）→ 入队 `BA_ClearBlock`/`BA_SettlePerk(TurnStart)`/`BA_ResetEnergy`/抽牌 → `PerformAllAsync` → `BE_PlayerTurnActiveStarted`（直发）。
  - 因此**开场格挡类不能挂 `BE_BattleStarted`/`BE_TurnStarted`**（会被随后的清格挡清掉、或排在 `BA_ResetEnergy` 之前被覆盖），正确落点是 `BE_PlayerTurnActiveStarted`（此时格挡已清、能量已重置、抽牌已完成）。
  - `BE_PlayerTurnEnded` 播出时格挡仍是本回合残留值（清除只发生在下回合开始）——奥利哈钢/斗篷扣等「回合结束」判据在此刻读取。
  - `BE_BattleEnded` 播完（含所有处理器）才 `player.EndCombat()`——燃烧之血在处理器内回血来得及，之后入队的动作无人消费。
  - 「玩家实际失血」判据：`ev.Amount - ev.Absorbed > 0`（Amount=修正后总伤害，Absorbed=格挡吸收）；「死亡的是敌人」判据：`ev.Creature != Context.Player.Creature`（引用比较）。
- **费用类操作**：`CardModel.Cost`（`ModifiableStat`）支持 `Add`；**战斗内永久性**增减（带刺手甲 +1、书签 -1）可行（战斗卡每场烘焙、无需恢复）；**本回合临时**修改（免费打出后恢复）不可行（`ModifiableStat` 无单条 modifier 移除）。

## 5. 排除明细（195 件，按原因分组）

### 5.1 伤害/格挡修正管线（18 件）

需要遗物参与 `Hook.Resolve` 数值管线（每帧预览与结算同源），属管线扩展，超出本轮边界。
