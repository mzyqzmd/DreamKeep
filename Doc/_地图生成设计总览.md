# 地图生成设计总览（Slay the Spire 2 / Godot C#）

> 分析视角：单人版（默认排除联机/同步层）。代码位置：`src/Core/Map/` 为主，运行时编排在 `src/Core/Runs/RunManager.cs`，UI 在 `src/Core/Nodes/Screens/Map/`。
> 本文档只描述**地图形状与节点类型的生成逻辑**，不展开战斗、事件、遗物具体数值。

---

## 1. 概览与定位

本工程的地图是一张**有向无环的节点图（DAG）**，纵向分层（行 = 楼层），横向分叉（列 = 走廊分支）。玩家从底部起点逐层向上，到达顶层 Boss。核心特点：

- **确定性**：整张地图由"运行种子 + 章节索引"推导出的子种子驱动，同种子可复现（`StandardActMap.CreateFor` → `Rng(seed, "act_{i}_map")`）。
- **分层生成**：先造"骨架路径"（拓扑），再分配"节点类型"（语义），再"剪枝"去重，最后"后处理"做视觉布局。
- **可修改**：生成后通过统一的 `Hook.ModifyGeneratedMap / ModifyGeneratedMapLate` 钩子链，让遗物、修饰符、卡牌在运行时改写地图（换底图、改类型计数、整体替换为另一种地图）。

## 2. 核心数据模型

### 2.1 `MapPoint`（节点）— `src/Core/Map/MapPoint.cs`
- 关键字段：`coord`（`MapCoord`）、`PointType`（`MapPointType`）、`CanBeModified`（是否允许被 Hook 改写）、`parents` / `Children`（`HashSet<MapPoint>`，双向边由 `AddChildPoint`/`RemoveChildPoint` 维护）。
- 图算法工具：`GetFirstCommonDescendant` / `GetCommonAncestor`（最近公共祖先/后代）、`BFS_FindPath`（BFS 求两节点路径）、`GetLastJunctionLength`（向上回溯到最近分叉）、`IsDescendantPathSame`（两条到公共后代的路径类型序列是否一致，供剪枝判定"重复段"使用）。
- `Quests`：节点可挂载任务（`AbstractModel` 列表），带 `NodeMarkedChanged` 事件。

### 2.2 `MapCoord`（坐标）— `src/Core/Map/MapCoord.cs`
- 仅 `col`/`row` 两个 `byte`，实现 `IEquatable`/`IComparable` 及网络序列化（`IPacketSerializable`，2 字节）。比较按 `(col,row)` 元组。

### 2.3 `MapPointType`（节点类型）— `src/Core/Map/MapPointType.cs`
```csharp
Unassigned, Unknown, Shop, Treasure, RestSite, Monster, Elite, Boss, Ancient
```
- `Ancient`：起点（固定，col 3 / row 0）。`Boss`：终点。`Unknown` 为"?"事件节点（进入时才揭晓具体事件）。其余为功能节点。

### 2.4 `MapPointState`（运行时可达性）— `src/Core/Map/MapPointState.cs`
```csharp
None, Travelable, Traveled, Untravelable
```
- 仅用于 UI 展示，不参与生成。由 `NMapScreen.RecalculateTravelability` 每帧/每次移动后重算（见 §6.3）。

## 3. 地图变体体系（ActMap 继承树）

`ActMap`（抽象基类，`src/Core/Map/ActMap.cs`）定义网格访问、行列枚举、`BossMapPoint`/`StartingMapPoint`/`SecondBossMapPoint` 等契约。具体变体：

| 类 | 用途 | 生成策略 |
|---|---|---|
| `StandardActMap` | **正常章节地图**（默认） | 7 条分叉路径 + 类型随机分配 + 剪枝 + 后处理 |
| `GoldenPathActMap` | 固定教学/引导路径 | 单列直线，16 个预置类型，无分支 |
| `SpoilsActMap` | 战利品/收尾地图 | "沙漏形"——所有路径先汇向中央宝藏行再扩散到 Boss |
| `SavedActMap` | 读档恢复 | 由 `SerializableActMap` 反序列化重建，不做随机 |
| `NullActMap` | 空占位（单例） | 不生成任何节点 |
| `MockActMap` | 测试占位 | 同上 |

正常流程走 `StandardActMap`；`SpoilsMap` 卡牌等可在生成钩子里整体替换为 `SpoilsActMap`。

## 4. 标准地图生成算法（重点）

入口：`StandardActMap` 构造函数（`src/Core/Map/StandardActMap.cs:70`）。

### 4.1 网格与种子
```
_mapWidth        = 7            // 列数固定
_mapLength       = GetNumberOfRooms(isMultiplayer) + 1   // 网格行数
Grid             = new MapPoint[7, _mapLength]
StartingMapPoint = (3, 0)       // 起点落在中列
BossMapPoint     = (3, _mapLength)        // Boss 在网格之外，单独存储
SecondBoss(可选) = (3, _mapLength + 1)    // 仅当 ActModel.HasSecondBoss
```
- 列恒为 7，确保宽度一致；行数 = 房间数 + 1。
- `GetNumberOfRooms`：单人 = `BaseNumberOfRooms`；多人 −1。`GetNumberOfFloors = 房间数 + 2`（含起点与 Boss 两层）。
- 固定行语义：**最后一行（row = _mapLength−1）恒为 `RestSite`**（Boss 前休整）；**倒数第 7 行（row = _mapLength−7）恒为 `Treasure` 或 `Elite`**（由 `shouldReplaceTreasureWithElites` 决定）；**第 1 行恒为 `Monster`**。

### 4.2 路径生成（拓扑骨架）
1. **7 条起点路径**：`GenerateMap` 在 row 1 随机生成 7 个起点（第 2 个保证与第 1 个不同），存入 `startMapPoints`，每个起点沿 `PathGenerate` 向下延伸。
2. **单步前进 `GenerateNextCoord`**：从当前节点向上一行（`row+1`），在 `{−1, 0, +1}` 三列候选中 `StableShuffle` 后依次尝试，要求**不越界、不与已有路径交叉**（`HasInvalidCrossover`）。
   - 交叉判定：若目标列已存在同 row 的节点且该节点的某个子节点正好朝**相反方向**偏移，则判定为"交叉"，跳过该候选。
3. **收口**：所有最后一行节点 `AddChildPoint(BossMapPoint)`；`StartingMapPoint` 连到全部 row-1 节点；有第二 Boss 时 `Boss → SecondBoss`。
- 由于"落到已存在坐标则复用节点"，7 条路径会在中途**自然汇合/分叉**，形成 DAG。

### 4.3 节点类型分配（`AssignPointTypes`）
- **固定行**：row 1 = Monster；row _mapLength−1 = RestSite；row _mapLength−7 = Treasure/Elite（不可改，`CanBeModified=false`）。
- **计数配额** `MapPointTypeCounts`（`src/Core/Map/MapPointTypeCounts.cs`）：
  - `NumOfElites` = `5`（若 `SwarmingElites` 升变则 ×1.6 ≈ 8），上限 `maxElites=15`。
  - `NumOfShops` = 3。
  - `NumOfUnknowns` = `NextGaussianInt(12, 1, 10, 14)`（高斯，约 10–14）。
  - `NumOfRests` = `NextGaussianInt(5, 1, 3, 6)`（约 3–6）。
  - 各 `ActModel` 可覆写 `GetMapPointTypes`（如 `Overgrowth` 把 rests 提到约 7，并受 `Gloom` 升变 −1）。
- **随机落点 + 合法性校验** `GetNextValidPointType` → `IsValidPointType`：
  - **下层限制**（row < 5）：禁止 `RestSite` / `Elite`。
  - **上层限制**（row ≥ _mapLength−3）：禁止 `RestSite`。
  - **父子限制**：`Elite/RestSite/Treasure/Shop` 不能与其 parent 或 child 同类型。
  - **兄弟限制**：`RestSite/Monster/Unknown/Elite/Shop` 不能与其兄弟（共享 parent 的其他子节点）同类型。
- **兜底**：所有仍未分配（Unassigned）的节点最终置为 `Monster`。
- 若某类型在所有合法位置都放不下，则退回 `Unassigned` 留给 Monster 兜底，`PointTypesThatIgnoreRules` 集合（默认空）可让特定类型跳过规则。

### 4.4 路径剪枝（`MapPathPruning.PruneDuplicateSegments`）
- 目的：消除"从某个分叉（parents≥2）出发、到某个汇合点（parents≥2）结束、且**类型序列与坐标序列完全一致**"的多条冗余平行段，提升路线多样性。
- 流程：`FindAllPaths`（从起点 DFS 出所有到 Boss 的路径）→ `AddSegmentsToDictionary`（按 `GenerateSegmentKey` = 起止坐标 + 类型序列建字典）→ `GetDuplicateSegments`（取出出现 >1 次的段）→ `PrunePaths`（随机保一段，删/断其余；带"断父子边"回退）。
- 最多 50 次迭代，失败抛异常（防御性）。

### 4.5 后处理布局（`MapPostProcessing`，生成后纯坐标调整，不改语义）
1. **`CenterGrid`**：若左右两侧整列空，则将整图平移 ±1 列，使地图在 7 列框内居中。
2. **`SpreadAdjacentMapPoints`**：逐行迭代，把每个节点移到"与同排邻居间隔最大"的合法列；合法列 = 其所有 parent/child 列的 ±1 交集（`GetAllowedPositions`），保证连线不被拉断。
3. **`StraightenPaths`**：对"恰好 1 父 1 子"且偏向一侧的中间节点，向内挪一格，使路径更直。

## 5. 特殊变体

### 5.1 `GoldenPathActMap`（固定路径）
- 单列直线（col 3），按 `_defaultPointTypes`（16 个预置类型：怪/未知/休整/宝藏/商店/精英 的固定序列）自上而下排布，无分支、无随机、无剪枝。
- 多人模式会 `RemoveAt(2)` 删掉一个节点缩短路径。用于教学首通体验。

### 5.2 `SpoilsActMap`（沙漏地图）
- `GenerateHourglassMap`：所有路径先向下**汇聚**到中央 `treasureRow`（= _mapLength−7）的唯一 `Treasure` 节点（`RedirectToTreasure` 把游散节点重定向过去），再向下**扩散**至 Boss。
- 宽度由 `GetAllowedColumnsForRow` 约束：距中央宝藏行越远 / 接近顶端越窄，形成"沙漏"轮廓。移动优先级 `BuildCenteredPriorityList` 让路径在远离宝藏行时向中列靠拢。
- 类型分配规则与 Standard 完全一致（复用同一套 `_*Restrictions` + `IsValidPointType`）。

## 6. 运行时集成

### 6.1 生成编排（`RunManager`，`src/Core/Runs/RunManager.cs:555` 附近）
```
if (存在本章节存档)  → new SavedActMap(存档) → Hook.ModifyGeneratedMapLate → AfterMapGenerated
else                 → State.Act.CreateMap()（= StandardActMap.CreateFor）→ Hook.ModifyGeneratedMap → AfterMapGenerated
                        （首章且未以 Neow 开局时，起点 PointType 改为 Monster）
State.Map = map;  NMapScreen.Instance?.SetMap(...)
```
- `MapSelectionSynchronizer.BeforeMapGenerated()` 在生成前调用（联机投票占位，单人版为空操作）。

### 6.2 移动（`MoveToMapCoordAction` → `RunManager.EnterMapCoord`）
- 玩家选点触发 `MoveToMapCoordAction`，经 `EnterMapCoord` → `AddVisitedMapCoord`（记录已访问坐标）→ `EnterMapCoordInternal` 进入对应房间。
- 已访问坐标集合驱动 UI 重算可达性。

### 6.3 可达性判定（`NMapScreen.RecalculateTravelability`）
- 已访问节点 = `Traveled`，其余先全置 `Untravelable`。
- 当前所在节点的**子节点** = `Travelable`（即只能走连出去的边）。
- 特例：若存在 `Flight` 修饰符，则**下一整行**都可达（无视分支，直接飞）。
- 到达 Boss 行后 Boss = `Travelable`；有第二 Boss 时，到 Boss 后第二 Boss 才 `Travelable`。

## 7. 修改地图的 Hook 体系（单人版相关）

生成后通过 `Hook.ModifyGeneratedMap`（早）/`ModifyGeneratedMapLate`（晚）遍历 `IterateHookListeners`，各模型可覆写同名方法改写地图。已知实现：

| 来源 | 方法 | 效果 |
|---|---|---|
| `GoldenCompass`（遗物） | `ModifyGeneratedMap` | 改写地图（揭示/替换点位类型） |
| `FurCoat`（遗物） | `ModifyGeneratedMapLate` | 晚期改写 |
| `BigGameHunter`（修饰符） | `ModifyGeneratedMap` | 用自定义 `MapPointTypeCounts`（更多精英）重建一张 `StandardActMap` |
| `SpoilsMap`（卡牌） | `ModifyGeneratedMap` / `ModifyGeneratedMapLate` / `AfterMapGenerated` | 整体替换为 `SpoilsActMap`（沙漏战利品图） |

> 这与项目整体的"Hook 监听链"架构一致：生成也走 `IterateHookListeners()`，单人版无需关心联机分支（联机仅 `MapSelectionSynchronizer` 一项，单人恒为空操作）。

## 8. 序列化与存档

- `SerializableActMap` / `SerializableMapPoint`（`src/Core/Saves/Runs/`）：保存网格宽高、各点（坐标/类型/CanBeModified/子坐标列表）、Boss/起点/第二 Boss、起始点集合。
- `SavedActMap`：按上述数据重建 `Grid` 与父子边（`WireChildren`），用于读档恢复，完全确定性、不重新随机。

## 9. 单人版借鉴要点（摘录）

1. **生成分阶段、可复现**：种子 → 拓扑 → 类型 → 剪枝 → 布局，每一步职责单一，便于单独测试/复用。
2. **固定语义行 + 配额随机**：用确定行（Boss 前休整、宝藏/精英行、首行怪）保证节奏，其余用高斯配额 + 合法性约束保证"不出怪异相邻"。
3. **合法性约束集合化**：`_lower/_upper/_parent/_child/_sibling` 五类限制用 `HashSet` 表达，新增类型约束只需改集合。
4. **DAG 而非纯树**：路径中途汇合/分叉，`HasInvalidCrossover` 防交叉、`PruneDuplicateSegments` 去重复段，是 roguelike 地图成熟的两条经验。
5. **布局与语义解耦**：`MapPostProcessing` 只在坐标层面做居中/散开/拉直，不影响类型与连线语义。
6. **Hook 改写而非特判**：换地图/改地图全走 `ModifyGeneratedMap` 链，避免战斗/遗物逻辑硬编码进生成器。
7. **可达性由"当前节点的子节点"决定**：移动规则极简；特殊能力（Flight）只需把"下一行全开"作为一处特例。
