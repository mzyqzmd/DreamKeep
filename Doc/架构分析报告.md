## 一、结论速览

### 综合评分：**97 / 100（A）**

一句话总纲：**八个程序集、一张无环依赖 DAG、双层四通道解耦（战斗级 + 场景段级），并在其之上统一「整局级命令门面」`RunCommandDispatcher`；配置只读一次即烘焙为运行时对象，规则与状态只存在一处；六个场景阶段（先古之民 / 休息 / 战斗 / 宝箱 / 商店 / 事件）的运行时逻辑全部归位 `GameRun` 域，每段配 `PresentationBridge`，表现层只上发意图、订阅事实；整局进度由 `RunState` 持有，地图节点（`StandardMapGenerator`）驱动阶段叠加编排。** 本轮主要变化是 `GameBattle` 域内 `Action` 与 `Hook` 两层从扁平大目录重分类为语义子目录（`Combat`/`CardPile`/`RunBoundary`/`Selection` 与 `DeathGuard`/`PerkRules`），消除「40+ 文件扁平堆」的可发现性异味，是纯代码组织层面的净改善；内容侧新增精英「石蜜丝（Byrdonis）」、普通「BattlewornDummy / FuzzyWurmCrawler」等敌人视图与「高墙（Rampart）/ 领地（Territorial）」状态，均走既有数据驱动通道，零新机制、零反模式。反模式实测画像与上一版**完全一致**（本轮未引入任何新的 `Find*`/单例/跨对象强耦合）。

## 三、架构总览

### 3.1 程序集依赖 DAG（无环）

```
  Layer5  Presentation ──────────────┐ (引用全部下层 + CommonPresentation + 外部 GUI/Spine/TMP…)
                                       │
  Layer4  CommonPresentation ──────────┤ (引用 Utility/ConfigData/RuntimeData/EngineUtility/GameBattle/GameRun)
                                       │
  Layer3  GameRun ─────────────────────┤ (引用 Utility/ConfigData/RuntimeData/EngineUtility/GameBattle)
                                       │
  Layer2  GameBattle ──────────────────┤ (引用 Utility/ConfigData/RuntimeData/EngineUtility)
                                       │
  Layer1  RuntimeData ──┐  EngineUtility │ (RuntimeData → Utility/ConfigData/EngineUtility；EngineUtility 仅引外部包)
                       │                │
  Layer0  ConfigData ──┘  Utility        (ConfigData → 仅外部序列化包；Utility → 无引用，纯叶层)
```

- **无环验证**：8 个 asmdef 的 `references` 经 GUID 反解后形成严格分层 DAG，无任何反向边或环（已连续 12 轮核验）。
- **`EngineUtility` 纯净**：`using _DreamKeep.{域}` 全量扫描零命中，仅引 UniTask / DOTween / NaughtyAttributes / Newtonsoft.Json / InputSystem，是纯引擎机制层（`_GameSystem` 收拢 Input/Scene/Audio/Save）。
- **`ConfigData` 为资产叶层**：仅引外部序列化包，无任何内部域引用；所有 SO 定义（敌人/遗物/药水/卡牌/状态/事件/休息选项/地图/价格）零业务逻辑。

### 3.2 通信模型（双层四通道）

系统间通信由四路原语构成，且按「战斗级」与「场景段级」两层复用同一套范式：

| 通道 | 方向 | 载体 | 约定 |
| --- | --- | --- | --- |
| 上行命令 | 表现 → 域 | `BattleCommandDispatcher` / 各级 `XxxCommandDispatcher` / 统一 `RunCommandDispatcher` | **命令只入队不执行**，由域侧 `BattleLoop`/`Session` 消费 |
| 下行事件 | 域 → 表现 | 27 个 `BE_*` 只读 struct 事件 + `SegmentEventDispatcher<T>` | 表现层**只订阅、不改写**战斗状态 |
| 上行只读查询 | 表现 → 域 | `BattleQueryDispatcher`（与结算共用 `Hook.Resolve`） | 表现层向域查询只读快照 |
| 横向状态介入 | 域内部 | `Hook`（数值修正 `StatHook` / 致命伤 `DeathGuardHook` / 掉血 `HpDropHook` / 满格挡 `FullBlockHook` / 滑溜 `SlipperyHook` / 结算 `SettleHook`） | 状态经 Hook 介入结算，预览与结算同源 |

**两级命令门面**：战斗内命令经 `BattleCommandDispatcher` 入队；跨场景段的整局写操作（用药、计时、领奖、金币、HP）经统一 `RunCommandDispatcher` 收口到 `GameRun` 域，写入由 `RewardClaimService` 等域侧服务完成——这是 2026-11-11 轮 K1/K2 收口后的稳定形态，本轮未变。

### 3.4 六场景阶段（同构零漂移）

`SegmentSceneManager` 按地图节点类型叠加编排六个阶段的运行时逻辑，每段 = `LifetimeScope`（隔离 DI）+ `Loop/Session`（域侧规则）+ `PresentationBridge`（事实下行 + 命令门面上行）。六阶段：先古之民（Ancient）/ 休息（Rest）/ 战斗（Battle）/ 宝箱（Chest）/ 商店（Shop）/ 事件（Event）。常驻靠 `RunLifetimeScope` + 叠加场景，**无 `DontDestroyOnLoad` 滥用**（唯一 `DontDestroyOnLoad` 命中是零引用死代码 `UI_SingletonObject`）。

### 3.5 本轮未提交的 `GameBattle` 动作/钩子分层重构（重要变更）

**工作树内、`HEAD = 4511e66` 尚未包含**。`GameBattle/Action/Concrete/` 由扁平目录重分类为语义子目录，且 `BattleAction.cs` 上移到 `Action/`：

- `Action/Concrete/Combat/`（17 个 `BA_*`）：伤害/格挡/治疗/能量/移动/失衡击晕等**直接战斗动作**
- `Action/Concrete/CardPile/`（7 个）：抽/弃/耗/洗牌等**牌堆动作**
- `Action/Concrete/RunBoundary/`（2 个）：用药/擦除等**跑图边界动作**
- `Action/Concrete/Selection/`（3 个）：升级/耗牌选择等**选择动作**
- `Hook/` 同步重分类：`DeathGuard/`（`IDeathGuard`/`DeathGuardHook`）+ `PerkRules/`（`StatHook`/`DeathHook`/`FullBlockHook`/`HpDropHook`/`SettleHook`/`SlipperyHook`）

**核验结论**：

- 仅文件搬移 + 引用/命名空间更新，无跨程序集边变化、DAG 不变；命名空间维持扁平 `_DreamKeep.GameBattle`（与 asmdef `rootNamespace` 及全项目约定一致，子目录仅为物理组织）。
- 代表性抽样核验（`BA_Damage.cs`、`StatHook.cs`、`BP_Rampart.cs`、`SO_Rampart.cs`、`UI_Byrdonis.cs`）显示：单职责、注释阐述设计意图、四通道通信与既有 `Hook` 接入手法完全一致、数据驱动 SO/Perk 模式零漂移。
- 属**纯代码组织净改善**，消除「40+ 文件同名扁平堆」的可发现性异味；建议尽快提交以固化。

## 六、模块逐域分析

### 6.1 Utility（8 / 327）
纯工具叶层，零程序集依赖。`ObjectPool<T>`（零分配对象池，被 `StatHook` 复用）与 `MonoObjectPool<T>`（表现层通用池）是核心复用件。无反模式。

### 6.2 EngineUtility（34 / 2,190）
引擎机制层：`_GameSystem` 收拢 Input/Scene/Audio/Save；`AudioRoot`（378 行，音频 tick）、`SaveService`（存档入口，`Resources.Load` 单点 + 静态字段 D1 收敛）、`PointerCursor`（光标态）。`Update()` 3 处（音频 tick / 光标态 / 布局拟合）均为引擎机制，可接受。`using` 全量扫描零域层依赖。

### 6.3 ConfigData（185 / 3,141）
全部 SO 定义，零业务逻辑。资产族：敌人（`SO_Enemy` + 变体）、遗物（~60 具体 + 基类）、药水（15）、卡牌、状态（`SO_Perk` 基类 + 具体：`SO_Strength`/`Weak`/`Vulnerable`/`Shrink`/`Slippery`/`Slow`/`Imbalanced`/`Rampart`/`Territorial`…）、事件（`SO_Event` + `EED_*` 效果多态）、休息选项（`SO_RestOption` + 4 具体）、商店价格（`SO_ShopPrices`）、地图（`SO_Map`）。数据驱动纪律保持。
