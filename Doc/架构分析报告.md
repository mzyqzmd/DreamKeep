## 一、结论速览

### 综合评分：**96 / 100（A）**

一句话总纲：**八个程序集构成一张无环依赖 DAG，双层四通道（战斗级 + 场景段级）解耦并由整局级命令门面 `RunCommandDispatcher` 统一收口写操作；配置只读一次即烘焙为运行时对象，规则与状态只存在一处；六个场景阶段运行时逻辑归位 `GameRun` 域，每段 = `LifetimeScope` + `Loop/Session` + `PresentationBridge`，整局进度由 `RunState` 持有，地图节点驱动阶段叠加编排。本轮以四个净改善增量推进（整局不重复抽取台账、滑溜结算改 Hook 钳制且预览同源、MaxHp 通知闭合、UI 协程改 UniTask 显式取消），反模式进一步收敛（协程归零、`FindObjectsOfType` 10→7）；但 `Presentation` 单程序集在精确文本口径下已越过 12k 拆分线，且新增一处死代码与若干过时注释，故总分较上一版 97 微降 1 分。**

## 二、评审范围与方法

- **范围**：`Assets/_Scripts` 全部 `.cs`（**711** 个，**34,037** 行，`wc -l` 口径）。不含 `Library`、`Packages`、`Assets/Plugins` 第三方源码；`Assets/Editor` 编辑器工具按约定不纳入。测试/调试设施按第 0 节声明排除评估。
- **统计口径说明**：全项目 65 个 `.cs` 末尾无换行（含 `Creature.cs`/`RunState.cs`/`UI_MapView.cs` 等），故 `wc -l` 与编辑器「总行数」存在差异；本报告统一采用 `wc -l`，并在 V-1 判断处同时给出精确口径，避免口径漂移。
- **方法**：
  1. 四路分域逐文件通读（数据/战斗层、整局/通用表现层、主表现层、本轮改动定向核验），不依赖历史摘要。
  2. 8 个 asmdef 的 `references` 全部核验（GUID ↔ asmdef 映射），做环路检测与方向核验；本轮 **asmdef 字节级未变**，无新增跨程序集边。
  3. 反模式关键词全量 grep（15 类），命中逐条核验文件与行号，区分业务代码与测试设施。
  4. 行数/命名族/超大文件统计（`>150` 行文件精确为 **42** 个；上一版记录的 40 为 `find -exec … +` 分批产生多个 `total` 行导致的口径偏差，本轮已修正）。
  5. 本轮 4 个提交逐 `git show/diff` 核验，确认删除符号零残留、改动不绕过不变量。

## 三、架构总览

### 3.1 程序集依赖 DAG（无环）

```
  Layer5  Presentation ──────────────┐ (引用全部下层 + CommonPresentation + 外部 GUI/Spine/TMP…)
  Layer4  CommonPresentation ──────────┤ (引用 Utility/ConfigData/RuntimeData/EngineUtility/GameBattle/GameRun)
  Layer3  GameRun ─────────────────────┤ (引用 Utility/ConfigData/RuntimeData/EngineUtility/GameBattle)
  Layer2  GameBattle ──────────────────┤ (引用 Utility/ConfigData/RuntimeData/EngineUtility)
  Layer1  RuntimeData ──┐  EngineUtility │ (RuntimeData → Utility/ConfigData/EngineUtility；EngineUtility 仅引外部包)
  Layer0  ConfigData ──┘  Utility        (ConfigData → 仅外部序列化包；Utility → 无引用，纯叶层)
```

- **无环验证**：8 个 asmdef 的 `references` 经 GUID 反解后形成严格分层 DAG，无反向边、无环；本轮零改动。
- **`EngineUtility` 纯净**：`using _DreamKeep.{域}` 在其 34 个文件中零命中，仅引 UniTask / DOTween / NaughtyAttributes / Newtonsoft.Json / InputSystem。
- **`ConfigData` 资产叶层**：25 个 SO 定义中 4 个含方法，但均为纯表查询（`SO_MapNodeVisual`/`SO_ShopPrices`/`SO_EnemySpeechLines`）或 `#if UNITY_EDITOR` 配置体检（`SO_RelicPool.OnValidate`），无玩法写入——「SO 零逻辑」实质成立。

### 3.2 通信模型（双层四通道）

| 通道 | 方向 | 载体 | 约定 |
| --- | --- | --- | --- |
| 上行命令 | 表现 → 域 | `BattleCommandDispatcher` / 各级 `XxxCommandDispatcher` / 统一 `RunCommandDispatcher` | **命令只入队不执行**，域侧消费（`DiscardPotionNow` 为显式声明的立即生效例外） |
| 下行事件 | 域 → 表现 | **34 个** `BE_*` 事件（`public struct : IBattleEvent`）+ 各段 `XEventDispatcher` | 表现层**只订阅、不改写** |
| 上行只读查询 | 表现 → 域 | `BattleQueryDispatcher`（与结算共用 `StatHook.Resolve` + `SlipperyHook.Clamp`） | 只读快照，零副作用 |
| 横向状态介入 | 域内部 | `Hook`（`StatHook`/`SettleHook`/`DeathGuardHook`/`PerkRules` 四组，含 `SlipperyHook`/`FullBlockHook`/`HpDropHook`/`DeathHook`） | 状态经 Hook 介入结算，预览与结算同源 |

> **修正说明**：上一版报告的「27 个 `BE_*` 只读 struct」与磁盘不符。实测为 **34 个普通 `public struct BE_* : IBattleEvent`**（`readonly struct` 命中 0），全部有实例化点、无死事件，事件属性只读。本轮按真实状态更正。

**两级命令门面**：战斗内命令经 `BattleCommandDispatcher` 入队（只 `Enqueue`，执行在 `RunLoop` 等待态出队后）；跨段整局写操作经 `RunCommandDispatcher` 收口，写域由 `GameRun` 域服务完成（含 `RewardClaimService` 的 `HashSet` 幂等去重与 `Stale`/`PotionSlotsFull` 重试语义）。

### 3.4 六场景阶段（同构零漂移）

`SegmentSceneManager`（298 行）按地图节点类型叠加编排六阶段：先古之民 / 休息 / 战斗 / 宝箱 / 商店 / 事件。每段 = `LifetimeScope`（隔离 DI）+ `Loop/Session`（域侧规则）+ `PresentationBridge`（事实下行 + 命令上发）。7 个 `*LifetimeScope`（含整局根）高度同构：装配期配置体检 → `Parent.Container.Resolve<RunState>()` → 构造 Session/Dispatcher/Loop → `RegisterInstance` + `RegisterComponentInHierarchy` + `RegisterEntryPoint` → `RegisterBuildCallback` 兜底注入游离 `UI_HoverTip`。常驻靠 `RunLifetimeScope` + 叠加场景，**无 `DontDestroyOnLoad` 滥用**。

### 3.5 本轮新增/改造的关键机制

**① 整局抽取台账（`RuntimeData/Run/RunDrawLedger.cs`，64 行）**
`HashSet<SO_Encounter>` / `HashSet<SO_Event>` 实现「整局不重复抽取」：`Draw(rng, pool, used)` 过滤已用后 `Rng.Pick` 并登记，候选耗尽只清本池；由 `RunState.cs:31` 持有（`DrawLedger { get; } = new()`）。遭遇抽取在组合根 `BattleLifetimeScope.cs:65` 接入，事件抽取在 `EventSession.cs:20`（原 `Rng.Pick` 改 `DrawLedger.DrawEvent`）；存档经 `RunStateRestore`（`CaptureDrawLedger`/`ResolveUsed`/GUID 扁平表）与 `RunStateSaveKeys`（`draw.encounters`/`draw.events`）持久化。性质：**整局域被动状态容器 + 只读查询**，不是视图、不绕过门面、无新增依赖边，随机流仍走整局 `Rng`，同种子可复现。

**② 滑溜结算改 Hook 钳制（预览与结算同源）**
旧实现经 `StatHook` 攻击修正通道且仅 `_applyModifiers && hpLoss > 0` 才消费，导致投掷/遗物伤害不吃上限。现改为 `SlipperyHook.Clamp(target, amount)`（有层数钳到 1），`BA_Damage.cs:34` / `BA_LoseHealth.cs:25` 结算前钳制，且 `BattleQueryDispatcher.cs:42,51` 的 `PreviewCardDamage`/`PreviewIntentDamage` 同步钳制——「真实掉血才消费」「预览与结算同源」两条不变量同时成立。`StatHook` 已移除 `BP_Slippery` 分派。

**③ MaxHp 通知闭合（`Creature.cs` +18 / `UI_TopBar.cs` +2）**
`MaxHp` 由 auto-property 改为 `_maxHp` backing field + private setter，判等后抛 `MaxHpChanged`；构造、`RestoreHpTo`、`RaiseMaxHp`、`LowerMaxHp` 全部写入点统一走 setter；`UI_TopBar` 订阅/退订 `MaxHpChanged → RefreshHp`。这是「HP 经 setter 通知」不变量向最大生命值的扩展，表现层无法直写域。

**④ UI 异步机制统一（`UI_MapView.cs`，346 行）**
`Coroutine` → `CancellationTokenSource _selectCts` + `UniTask.Delay(...).SuppressCancellationThrow().Forget()`；`OnDisable`/`OnDestroy` 均 `CancelSelect()`（Cancel + Dispose + 置空），异步体局部捕获 `cts_` 并以 `canceled || _selectCts != cts_` 双重判定防竞态。`Build(MapGraph)` 内联进 `[Inject] Construct(RunState)`。**全库 `StartCoroutine` 归零**，隐式「失活必须清引用」约定改为显式取消，属净改善。
