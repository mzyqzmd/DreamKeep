## 一、结论速览

### 综合评分：**95 / 100（A）**

一句话总纲：**八个程序集、一张无环依赖 DAG、双层四通道解耦（战斗级 + 场景段级）；配置只读一次即烘焙为运行时对象，规则与状态只存在一处；六个场景阶段（先古之民 / 休息 / 战斗 / 宝箱 / 商店 / 事件）的运行时逻辑全部归位 `GameRun` 域，每段配 `PresentationBridge`（事实下行 + 命令门面上行），表现层只做编排、不持业务规则；整局进度由 `RunState` 持有，地图节点（`StandardMapGenerator`）驱动阶段叠加编排。自上一版以来的去债（存档键集中管理 D6、场景装载假注释清理 F3、装配期查找 3→1、存档静态字段 6→4、目录重组与发奖去遭遇化）构成净改善，未引入新反模式。**

## 二、评审范围与方法

- **范围**：`Assets/_Scripts` 全部 `.cs`（654），不含 `Library`、`Packages`、第三方源码（`Assets/Plugins`）。`Assets/Editor` 仅工具脚本，不影响运行时架构。
- **方法**：
  1. 逐模块通读骨干与全部新增/变更文件（4 个 Explore 子代理分域审阅 + 主代理核验），不依赖历史摘要。
  2. 8 个 asmdef 的 `references` 全部反解为具体程序集（GUID ↔ asmdef 映射逐条核对），做环路检测与方向核验。
  3. 反模式关键词全量 grep（15 类），命中逐条核验文件与行号。
  4. **MonoBehaviour 引用核验按脚本 GUID 扫场景/预制体**，不只按类名 grep（类名 grep 会漏掉 YAML 里 `m_Script: {fileID: 11500000, guid: ...}` 形态的挂载）。
  5. 行为等价类改动给出「随机流是否变化 / 事件时机是否变化 / 序列化字段是否变化」三项结论。

## 三、架构总览

### 3.1 程序集依赖 DAG（无环）

```
                     ┌───────────────┐
       ┌────────────►│  ConfigData   │◄───────────┐
       │             └───────────────┘            │
       │        ┌──────────────┐                  │
       │        │   Utility    │◄──┐              │
       │        └──────────────┘   │              │
       │             ┌─────────────┴──┐           │
       ├────────────►│  RuntimeData   │◄──┐       │
       │             └────────────────┘   │       │
       │                    │             │       │
┌──────┴────────┐    ┌──────┴───────┐     │       │
│ EngineUtility │    │  GameBattle  │◄────┤       │
└──────┬────────┘    └──────┬───────┘     │       │
       │                    │             │       │
       │             ┌──────┴───────┐     │       │
       └────────────►│   GameRun    │◄────┘       │
                     └──────┬───────┘             │
                            │                     │
                     ┌──────┴─────────────┐       │
                     │ CommonPresentation │◄──────┤
                     └──────┬─────────────┘       │
                            │                     │
                     ┌──────┴──────┐              │
                     │Presentation │◄─────────────┘
                     └─────────────┘
```

- 程序集构成（当前行数）：`Utility`(8/327) ← `ConfigData`(174/2,974) ← `RuntimeData`(71/4,286) ← `GameBattle`(85/2,734) ← `GameRun`(117/3,189) ← `CommonPresentation`(47/4,244) ← `Presentation`(118/11,231)；`EngineUtility`(34/2,190) 为引擎桥接层，被 `CommonPresentation`、`Presentation` 引用，**`RuntimeData` 是唯一反向引用它的域程序集**。
- `Utility` 零外部引用（不引 UniTask、不引 DOTween、不引 Newtonsoft），纯 C# 叶层。
- `EngineUtility` 经 `using _DreamKeep.{GameBattle|GameRun|RuntimeData|ConfigData|Utility|CommonPresentation|Presentation}` 全量扫描**零命中**，asmdef `references` 仅 `UniTask`/`DOTween.Modules`/`NaughtyAttributes.Core`/`Unity.Newtonsoft.Json`/`Unity.InputSystem`——纯引擎件、不引任何域层，已重申确认。

### 3.2 通信模型

| 通道 | 战斗级 | 场景段级 |
| --- | --- | --- |
| 命令上行 | `BattleCommandDispatcher` | `XxxCommandDispatcher`（各段一个） |
| 事件下行 | `BattleEventDispatcher` | `SegmentEventDispatcher<TEvent>` + 各段一行子类 |
| 只读查询 | `BattleQueryDispatcher` | 段 Loop 的只读属性 / `[Inject] RunState` |
| 状态介入 | `IBattleEvent` 订阅方（遗物/Hook） | 段 Loop 内部规则经 `RunState` 受控入口 |

两份下行分派器（`BattleEventDispatcher` / `SegmentEventDispatcher`）的 `Register` 两重载与 `DispatchAsync` 逐字相同，刻意不合并：`GameBattle` 不能反引 `GameRun`，唯一可落点 `RuntimeData` 会把「分派原语」塞进纯数据层。两份文件摘要已互相指路。
