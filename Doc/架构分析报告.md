## 一、结论速览

### 综合评分：**97 / 100（A）**

一句话总纲：**八个程序集、一张无环依赖 DAG、双层四通道解耦（战斗级 + 场景段级），并在其之上统一「整局级命令门面」`RunCommandDispatcher`；配置只读一次即烘焙为运行时对象，规则与状态只存在一处；六个场景阶段（先古之民 / 休息 / 战斗 / 宝箱 / 商店 / 事件）的运行时逻辑全部归位 `GameRun` 域，每段配 `PresentationBridge`，表现层只上发意图、订阅事实；整局进度由 `RunState` 持有，地图节点（`StandardMapGenerator`）驱动阶段叠加编排。** 本轮主要变化是新增两类跨阶段复用系统——**百科大全（Encyclopedia）**与**开发者日志（DevelopLog）**——以及若干敌人视图/状态/动作内容；二者全部以既有数据驱动 + DI + 四通道范式零漂移落地，**无新增缺陷、无新增反模式**。

| 维度 | 得分 | 说明 |

## 三、架构总览

### 3.1 程序集依赖 DAG（无环）

```
  Layer5  Presentation ──────────────┐ (引用全部下层 + CommonPresentation + 外部 GUI/Spine/TMP…)
                                       │
  Layer4  CommonPresentation ──────────┤ (引用 Utility/ConfigData/RuntimeData/EngineUtility/GameBattle/GameRun)
                                       │
  Layer3  GameRun ─────────────────────┤ (引用 Utility/ConfigData/RuntimeData/EngineUtility/GameBattle)
                                       │
  Layer2  GameBattle ──────────────────┤ (引用 Utility/ConfigData/RuntimeData/EngineUtility)
                                       │
  Layer1  RuntimeData ──┐  EngineUtility │ (RuntimeData → Utility/ConfigData/EngineUtility；EngineUtility 仅引外部包)
                       │                │
  Layer0  ConfigData ──┘  Utility        (ConfigData → 仅外部序列化包；Utility → 无引用，纯叶层)
```

- **无环验证**：8 个 asmdef 的 `references` 经 GUID 反解后形成严格分层 DAG，无任何反向边或环。
- **`EngineUtility` 纯净**：`using _DreamKeep.{域}` 全量扫描零命中，仅引 UniTask / DOTween / NaughtyAttributes / Newtonsoft.Json / InputSystem，纯引擎机制层。
- **`ConfigData` 为资产叶层**：仅引外部序列化包，无任何内部域引用；所有 SO 定义零业务逻辑。

### 3.2 通信模型（双层四通道）

| 通道 | 方向 | 载体 | 约定 |
| --- | --- | --- | --- |
| 上行命令 | 表现 → 域 | `BattleCommandDispatcher` / 各级 `XxxCommandDispatcher` / 统一 `RunCommandDispatcher` | **命令只入队不执行**，由域侧消费 |
| 下行事件 | 域 → 表现 | 27 个 `BE_*` 只读 struct 事件 + `SegmentEventDispatcher<T>` | 表现层**只订阅、不改写** |
| 上行只读查询 | 表现 → 域 | `BattleQueryDispatcher`（与结算共用 `Hook.Resolve`） | 表现层向域查询只读快照 |
| 横向状态介入 | 域内部 | `Hook`（`StatHook`/`SettleHook`/`DeathGuard`/`PerkRules`） | 状态经 Hook 介入结算，预览与结算同源 |

**两级命令门面**：战斗内命令经 `BattleCommandDispatcher` 入队；跨场景段的整局写操作经统一 `RunCommandDispatcher` 收口到 `GameRun` 域，写入由 `RewardClaimService` 等域侧服务完成（K1/K2 收口后的稳定形态）。

### 3.3 八个有实质代码的域

| 域 | 文件 / 行 | 职责 |
| --- | --- | --- |
| Utility | 8 / 327 | 通用工具（对象池、确定性随机、可修正数值） |
| ConfigData | 185 / 3,141 | 全部 ScriptableObject 配置（零逻辑） |
| EngineUtility | 34 / 2,190 | 引擎机制层（Input/Scene/Audio/Save/UI 基础设施） |
| RuntimeData | 79 / 4,585 | 运行时实体与烘焙（玩家/敌人/生物/卡牌/状态/整局 `RunState`/地图） |
| GameBattle | 100 / 3,196 | 战斗域（动作系统/事件分发/钩子/结算/战斗段编排） |
| GameRun | 124 / 3,469 | 整局域（六阶段 `Loop/Session`、遗物/奖励/命令门面） |
| CommonPresentation | 53 / 4,937 | 通用表现层（卡牌视图/弹板/飘字/VFX/百科大全/开发者日志） |
| Presentation | 129 / 11,933 | 各场景阶段表现层（战斗/地图/顶栏/休息/宝箱/商店/事件/主菜单） |

### 3.4 六场景阶段（同构零漂移）

`SegmentSceneManager` 按地图节点类型叠加编排六个阶段，每段 = `LifetimeScope`（隔离 DI）+ `Loop/Session`（域侧规则）+ `PresentationBridge`（事实下行 + 命令门面上行）。六阶段：先古之民（Ancient）/ 休息（Rest）/ 战斗（Battle）/ 宝箱（Chest）/ 商店（Shop）/ 事件（Event）。常驻靠 `RunLifetimeScope` + 叠加场景，**无 `DontDestroyOnLoad` 滥用**。

### 3.5 本轮新增的跨阶段系统

**百科大全（Encyclopedia，7 文件 / 480 行，`CommonPresentation/System/Encyclopedia/`）**
- `UI_EncyclopediaPanel`（58 行，根编排器，`CloseRequested` 事件式收合）+ 三子页 `UI_CardEncyclopediaPanel`(194)/`UI_RelicEncyclopediaPanel`(141)/`UI_PotionEncyclopediaPanel`(77) + 排序枚举 `EEncyclopediaCardSortMode`(10)。
- 全部 `[Inject] Construct(PopFactory)` 注入、`MonoObjectPool` 池化、`CardModelBaker.Bake` 烘焙、**升级预览用 `CardModel.ToMutable().Upgrade()`（原型只读、域内真卡零写入）**——与「预览/结算同源」不变量完全一致；子页返回键只上报意图，开合编排归根面板。经 `RunLifetimeScope` 装配期注入（同 `UI_HoverTip` 模式）。

**开发者日志（DevelopLog，2 文件，`CommonPresentation/System/MainMenu/DevelopLog/`）**
- `UI_DevelopLogPanel`/`UI_DevelopLogBar`，主菜单内展示开发进度，经 `MainMenuFlow` 接线（与设置/放弃/百科同属常驻弹层互斥组）。

二者均为「跨阶段复用系统放进 `CommonPresentation`」的典型落地，零反向依赖、零反模式。

## 六、模块逐域分析

### 6.1 Utility（8 / 327）
纯工具叶层，零程序集依赖。`MonoObjectPool<T>`（表现层通用池，被百科/开发者日志/各类弹板复用）与 `ModifiableStat`（加值+乘率+上下限折叠、支持池化/克隆）是核心复用件。

### 6.2 EngineUtility（34 / 2,190）
引擎机制层：`_GameSystem` 收拢 Input/Scene/Audio/Save；`AudioRoot`（音频 tick）、`SaveService`（存档入口，`Resources.Load` 单点 + 静态字段 D1 收敛）、`PointerCursor`（光标态）。`Update()` 3 处（音频 tick / 光标态 / 布局拟合）均为引擎机制。`using` 全量扫描零域层依赖。

### 6.3 ConfigData（185 / 3,141）
全部 SO 定义，零业务逻辑。资产族：敌人、遗物（~60 具体）、药水（15→17）、卡牌、状态（`SO_Rampart`/`SO_Territorial` 为本轮新增）、事件（`SO_Event` + `EED_*` 效果多态）、休息选项（4）、商店价格、地图。数据驱动纪律保持。

### 6.4 RuntimeData（79 / 4,585）
运行时实体与烘焙：`Player`/`Enemy`/`Creature`（HP 经 setter 抛通知）、`RunState`（整局进度，仅 3 处检查点写入）、`StandardMapGenerator`（7 列可复现 DAG）、`CardModel`/`PerkBaker`（本轮新增 `BP_Rampart`/`BP_Territorial` 登记）。`RunState → EngineUtility` 是唯一向上边（存档接口）。

### 6.5 GameBattle（100 / 3,196）
战斗域核心。动作系统（`BattleAction` + `BA_*`，分 `Combat`/`CardPile`/`RunBoundary`/`Selection` 四子目录；本轮新增 `BA_RampartBlock`/`BA_Move`）、事件分发（27 个 `BE_*` 只读 struct）、钩子（`DeathGuard`/`PerkRules`）、结算（`BattleLoop` + `BP_BattleFinish`）、战斗段编排（`BattleSession`）。`BA_RampartBlock` 执行期按阵营解析盟友、复用 `BA_Block` 结算，四通道接入手法一致。

### 6.6 GameRun（124 / 3,469）
整局域。六阶段 `Loop/Session` 归位此域；`RunCommandDispatcher`（统一整局命令门面）+ `RewardClaimService`（幂等领奖）收口写操作；`RelicRoller`（遗物抽取，~57 运行时效果经 `RelicBaker` 类型分派、末位 `throw` 兜底）。`RunState` 持有整局进度，表现层 `[Inject]` 只读。

### 6.7 CommonPresentation（53 / 4,937）
通用表现层：卡牌视图、弹板（`UI_RewardPanel` 经 `RunCommandDispatcher` 上报）、飘字、VFX 工厂、点击声，**以及本轮新增的百科大全与开发者日志两类跨阶段系统（§3.5）**。**不再直写 `GameRun`**（K1 收口）。

### 6.8 Presentation（129 / 11,933）
各场景阶段表现层。`SegmentSceneManager`（按节点叠加编排，无上帝协调器）、`RunLifetimeScope`（常驻装配，含 2 处合法 `FindFirstObjectByType`）、地图套件、手牌区（`UI_HandView` 编排器 + 协作组件）、战斗 Actor 视图（本轮新增 `UI_Byrdonis`/`UI_BattlewornDummy`/`UI_FuzzyWurmCrawler`，均 `UI_Enemy` 子类、`const` 动画名、`BE_*` 事件订阅）、`MainMenuFlow`（接入百科 + 开发者日志入口）。体量最大，逼近拆分触发线（V-1）。
