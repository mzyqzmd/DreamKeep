### 3.1 程序集依赖 DAG（无环）

```

            ┌────────────►│ ConfigData  │◄──────────┐
            │             └─────────────┘           │
            │                    │                  │
            │             ┌──────┴──────┐           │
            │             │   Utility   │◄──┐       │
            │             └─────────────┘   │       │
            │                    │          │       │
            │             ┌──────┴──────┐   │       │
            ├────────────►│ RuntimeData │◄──┘       │
            │             └─────────────┘           │
            │                    │                  │
   ┌────────┴───────┐     ┌──────┴──────┐          │
   │ EngineUtility  │     │ GameBattle  │◄─────────┤  (→ Utility, RuntimeData, ConfigData)
   └────────┬───────┘     └──────┬──────┘          │
            │  (→ UniTask,       │                 │
            │    DOTween)        │                 │
            │             ┌──────┴──────┐          │
            └────────────►│   GameRun   │◄─────────┘  (→ GameBattle, RuntimeData, ConfigData, Utility)
                          └──────┬──────┘
                                 │
                          ┌──────┴──────┐
                          │CommonPresent│◄──────────┐ (→ Utility, ConfigData, RuntimeData,
                          └──────┬──────┘          │   EngineUtility, GameBattle, GameRun)
                                 │                 │
                          ┌──────┴──────┐          │
                          │ Presentation │◄────────┘ (→ CommonPresentation + 上述全部域)
                          └─────────────┘
```

- **叶层**：`Utility`（纯泛型基础设施，零内部引用）、`ConfigData`（纯 `ScriptableObject` 数据，零内部引用，仅外部包）。
- **中间层**：`RuntimeData → {Utility, ConfigData}`；`EngineUtility →`（仅 UniTask、DOTween 外部包，无内部引用）。
- **领域层**：`GameBattle → {Utility, RuntimeData, ConfigData}`；`GameRun → {GameBattle, RuntimeData, ConfigData, Utility}`。
- **表现层**：`CommonPresentation`（通用表现组件）与 `Presentation`（场景编排）**平级**；`Presentation → CommonPresentation` 为故意设计；二者均只向下依赖领域层，无反向引用。

### 3.2 双层四通道通信模型

**战斗级（GameBattle 内）**——既有的四通道：
1. **上行命令**：`BattleCommandDispatcher.PlayCard/EndTurn/UsePotion` → `BattleLoop.EnqueueCommand(new BC_*)`；`BC_*` 为纯数据载荷，处理逻辑拆至 `IBattleCommandReceiver.HandleCommand`，`BattleLoop` 在等待态分派（「句柄拆分」）。
2. **下行事件**：`BattleEventDispatcher` 广播 `BE_*`（`struct : IBattleEvent`，只读）。
3. **上行只读查询**：`BattleQueryDispatcher.PreviewCardDamage` → `StatHook.Resolve(...)`。
4. **横向状态介入**：`StatHook.Resolve` / `SettleHook.Settle` / `DeathGuardHook.TryPreventDeath`（经 `IDeathGuard`）。

**场景段级（每段 `GameRun/.../PresentationBridge`）**——「段域化」后沉淀的新四通道：
1. **命令上行**：UI 经注入的 `XxxCommandDispatcher`（如 `ShopCommandDispatcher`）提交语义意图（`BuyCard`/`RequestRemoval`…），门面转交段 `Loop/Session`。
2. **事实下行**：`SegmentEventDispatcher<TEvent>` 广播域事实（`SE_ShelfUpdated`/`EE_OptionsOffered`/`REE_OptionsOffered`…），UI 订阅刷新。
3. **只读查询**：UI 经 `[Inject] RunState` 读活体状态（地图/顶栏场景）或快照事实（商店货架 `ShopShelfSnapshot`）。
4. **状态介入**：段规则在 `GameRun` 域内修改 `RunState`（经受控入口），表现层不直接改域状态。

### 3.3 场景阶段与整局层

## 四、分模块分析

### 4.1 Utility（7 文件 / 247 行）· 叶层
纯泛型基础设施：`ModifiableStat`（加值×乘率+上下限折叠，支持 `Clone`）、`Rng`（同种子可复现）、`ObjectPool`、`StateMachine`。**零内部引用**，仅依赖 `System`/`Collections.Generic`。无反模式。

### 4.2 ConfigData（165 / 2,745）· 叶层（纯数据）
全部为 `ScriptableObject` 数据资产，**零运行时逻辑**：遗物 `SO_Relic` 基类 + ~60 具体配置；药水 `SO_Potion` + ~15 具体；事件 `SO_Event` + `EED_*` 效果数据 ~10；休息 `SO_RestOption` + 4 具体；商店价格 `SO_ShopPrices`；地图配置 `SO_Map`/`MapConfig`；另含 Actor（Perk/Intent/Affix 纯数据）、Card/Affix、Background、Ancient、Encounter、Shop。`using` 仅 `UnityEngine`/`System`/`NaughtyAttributes`，**零 `_DreamKeep.*` 引用**，数据驱动纪律完好。

### 4.3 RuntimeData（43 / 1,754）
运行时模型与状态系统：`CardModel/CM_Runtime`（156，持 `ModifiableStat` 成本、基础/追加/生效词条、`Clone/Upgrade/RebuildActive`）、`CardModelBaker`（161，烘焙原型 + 解析升级补丁）；状态 `ModifiableStat`/`EStatChannel`/`StatHook`（遍历宿主 perk → `GetModifier` → 折叠）；状态效果 `BattlePerk` + 5 个 `BP_*`（Strength/Dexterity/Weak/Vulnerable/Regen）+ `PerkBaker` + `SettleHook.Settle`（`BP_Regen` 产出 `BA_Heal`）；`Creature`（HP/MaxHp，setter 抛 `HpChanged`/`Healed`）。引用仅 `Utility`+`ConfigData`，**无向上违例**。持 `Sprite` 图标属引擎资产引用（非场景 GameObject），可接受。

### 4.4 EngineUtility（16 / 967）
表现与引擎桥接：`MonoObjectPool<T>`、Rng 辅助、UI 工具（含 `UI_SingletonObject` 死代码，见 §7 K5）。`using` 仅外部包（UniTask、DOTween、UnityEngine、EventSystems），**零内部引用**，依赖纯净。

### 4.5 GameBattle（77 / 2,482）· 战斗领域
四通道战斗通信中枢（见 §3.2）。`BattleAction` 抽象基类 `Execute→List<IBattleEvent>` 为无状态数据包；`ActionSystem` 串行排空、逐动作 await 演出；`BA_Damage`/`BA_Block` 经 `StatHook.Resolve` 取状态修正，`BA_Damage`/`BA_LoseHealth` 在战斗域内改 `Creature.CurrentHp`（合法，经 setter 通知，致命由 `DeathGuardHook` 拦截）。**「句柄拆分 + 收尾裁决下沉」**：`BC_*` 现为纯数据，处理逻辑拆至 `IBattleCommandReceiver`；胜负裁定移入域——`BattleContext.IsVictory/IsDefeat/IsBattleOver` + `BP_BattleFinish` 派发 `BE_BattleEnded` 并清场，`BattleLoop` 据 `IsVictory` 向上汇报。引用 `Utility`+`RuntimeData`+`ConfigData`+外部包，**无向上违例**，无反模式。唯一 TODO：`Player.cs`（法球槽位占位）。

### 4.6 GameRun（138 / 4,976）· 整局领域层（段域化核心）
- **`RunState`（188）**：持有配置/玩家/整章地图/RNG/兜底池；暴露**受控写入口** `GainGold`/`SpendGold`/`RestoreGoldTo`/`SpendPlayerHp`/`RestorePlayerHp`/`RestorePlayerHpTo`/`AddCard`/`AddRelic`/`TryAddPotion`/`RecordCardRemoval`/`EnterMapNode`/`CompleteMapNode`；金币/楼层变更抛 `GoldChanged`/`FloorChanged`，HP 变更经 `Creature.CurrentHp` setter 抛 `HpChanged`/`Healed`。
- **`RunFlow`（静态、零状态）**：`SegmentKindOf(EMapPointType)` 以 `switch` 把地图节点类型映射到六段；转换由 `MapGraph` 可达性状态机驱动（`Traveled`/`InProgress`/`Travelable`）。
- **六段 Loop/Session**：每段业务规则现 **全部落在 `GameRun` 域**，且只经 `RunState` 受控入口改写状态——`ShopSession.TryBuyCard` → `_run.SpendGold(price)` + `_run.Player.AddCard(...)`；`AncientLoop` → `_run.GainGold/SpendPlayerHp/Player.AddCard`；`RestLoop` → `_run.RestorePlayerHp/Player.AddRelic/Creature.RaiseMaxHp`；`EventSession.ApplyInstantEffect` → `_run.SpendGold/GainGold/SpendPlayerHp/RestorePlayerHp/Player.AddCard/AddRelic`；`ChestSession.Claim` → `_run.Player.AddRelic`。**HK-1 已闭环**：未发现任何 `_run.Gold -=` 或 `CurrentHp =` 裸写（仅 `RunState` 内部 setter 与两段 `Creature.RaiseMaxHp` 经 setter 通知）。
- **每段 `PresentationBridge`**：`SegmentEventDispatcher<TEvent>`（下行事实）+ `XxxCommandDispatcher`（上行命令门面），事实为 `IShopEvent`/`IEE_Event`/`IREE_Event` 等 `struct`，仅携只读数据。
- **地图系统**（`Run/Map` + `Run/Map/Model`）：`StandardMapGenerator.Generate`（423）生成 7 列网格 DAG（拓扑→类型分配→剪枝→可达性→布局），全程同 RNG 可复现；`IsRowLegal` 行规则 + `RunState.RollUnknownReveal` 问号节点按权重掷真实类型；模型 `MapNode`/`MapGraph`/`MapCoord`/`EMapNodeState`。
- **遗物系统**（`Run/Relic`）：`RelicBaker.Bake` 以 `switch(config_)` 全量登记 51 种 `RE_*` + 显式 `null` 豁免 10 种纯局外效果，默认分支 `_ => throw` 防静默失效；`RelicRoller` 跳过已持有/断引用，池空降级兜底池。

### 4.7 CommonPresentation（33 / 3,391）· 通用表现组件
共享 UI 组件：`UI_CardFace`（262，卡面绑定/可打外观/涟漪/数值预览）、`UI_CardSelectPanel`（334，抽象基类：陈列/确认/编排）、`UI_HoverTip`（210，显隐/内容/指针事件）、`UI_RewardPanel`（192）、`UI_SmithForgeVfx`（202）。`using` 仅允许集合内（含 `GameRun`/`GameBattle`），**无 `Presentation` 反向引用**。反模式：含 `UI_SingletonObject` 零引用死代码（见 §7）。

## 五、关键系统设计

1. **六阶段 + 整局层落地**：`RunState`（纯 C#）持有整局进度，`SegmentSceneManager` 按地图节点叠加编排，`RunLifetimeScope` 注册常驻件，七个 `*LifetimeScope` 各自隔离装配；**无 `DontDestroyOnLoad` 滥用**（唯一命中为零引用死代码 `UI_SingletonObject`）。
2. **四通道通信已双层接通**：战斗级（命令/事件/查询/介入）+ 场景段级（每段 `PresentationBridge` 事实下行 + 命令门面上行），无平行机制。
3. **地图系统数据驱动**：`StandardMapGenerator` 参数化生成可复现 7 列 DAG，揭示规则 `/RollUnknownReveal` 同 RNG；选点经受控入口触发对应段。
4. **遗物/药水/事件/休息配置系统**：`SO_Relic`+`RE_*`、`SO_Potion`+`BP_*`、`SO_Event`+`EED_*`、`SO_RestOption`+4 具体，全部经 Baker 类型分派（`_ => throw` 兜底），内容扩充零漂移。
