## 二、评审范围与方法

- **范围**：`Assets/_Scripts` 全部 `.cs`（**747** 个，**35,052** 行，`find … -exec cat {} + | wc -l` 口径）。不含 `Library`、`Packages`、`Assets/Plugins` 第三方源码；`Assets/Editor` 编辑器工具按约定不纳入。测试/调试设施按第 0 节声明排除评估。
- **统计口径说明**：全项目多个 `.cs` 末尾无换行，故 `wc -l` 与编辑器「总行数」存在差异；本报告统一采用上述 `cat` 汇总口径。上一版的 `Presentation` 记为 11,978（`find -exec wc -l +` 分批口径）/ 精确 12,021，本轮统一为 **12,023**，两种口径不可直接相减。
- **方法**：
  1. 四路分域逐文件通读（数据/战斗层、配置/通用表现层、战斗表现修复、全局不变量与元信息），不依赖历史摘要。
  2. 8 个 asmdef 的 `references` 经 GUID 反解核验，做环路检测与方向核验；**本轮 asmdef 字节级未变**，无新增跨程序集边。
  3. 反模式关键词全量 grep（15 类），命中逐条核验文件与行号，区分业务代码与测试设施。
  4. 行数/命名族/超大文件统计（`>150` 行文件精确 **42** 个；最大 `UI_HandView` 512 / `StandardMapGenerator` 423 / `UI_PotionGroup` 413）。
  5. 7 个提交逐 `git show/diff` 核验，确认删除符号零残留、改动不绕过不变量；对子代理结论冲突处（同源性、N-1/N-2、Z-1）亲自读源码复核。

## 三、架构总览

### 3.1 程序集依赖 DAG（无环）

```
  Layer5  Presentation ──────────────┐ (引用全部下层 + CommonPresentation + 外部 GUI/Spine/TMP…)
  Layer4  CommonPresentation ──────────┤ (引用 Utility/ConfigData/RuntimeData/EngineUtility/GameBattle/GameRun)
  Layer3  GameRun ─────────────────────┤ (引用 Utility/ConfigData/RuntimeData/EngineUtility/GameBattle)
  Layer2  GameBattle ──────────────────┤ (引用 Utility/ConfigData/RuntimeData/EngineUtility)
  Layer1  RuntimeData ──┐  EngineUtility │ (RuntimeData → Utility/ConfigData/EngineUtility；EngineUtility 仅引外部包)
  Layer0  ConfigData ──┘  Utility        (ConfigData → 仅外部序列化包；Utility → 无引用，纯叶层)
```

- **无环验证**：8 个 asmdef 的 `references` 经 GUID 反解后形成严格分层 DAG，无反向边、无环；本轮零改动。新增的 5 个 Hook 均为 `GameBattle` 内部 `internal static` 类，`BattlePerkQuery` 位于 `RuntimeData`，**不产生新跨程序集边**。
- **`EngineUtility` 纯净**：34 个文件中 `using _DreamKeep.{域}` 零命中，仅引 UniTask / DOTween / NaughtyAttributes / Newtonsoft.Json / InputSystem。
- **`ConfigData` 资产叶层**：新增 14 个 `SO_Perk` 具体类均为 `sealed`、仅 `[CreateAssetMenu]` + override `Name`/`SettleTiming` + 少量 `[SerializeField]` 数值，零方法体、零玩法逻辑；`SO_MyceliumWhisper` 为空类 `: SO_Event`，数据全在 `.asset` 的 `[SerializeReference]` 多态效果中。纪律保持。

### 3.2 通信模型（双层四通道）

| 通道 | 方向 | 载体 | 约定 |
| --- | --- | --- | --- |
| 上行命令 | 表现 → 域 | `BattleCommandDispatcher` / 各级 `XxxCommandDispatcher` / 统一 `RunCommandDispatcher` | **命令只入队不执行**，域侧消费（`DiscardPotionNow` 为显式声明的立即生效例外） |
| 下行事件 | 域 → 表现 | **34 个** `BE_*` 事件（`public struct : IBattleEvent`）+ 各段 `XEventDispatcher` | 表现层**只订阅、不改写**；本轮 `InvokeSafely` 为异常路径加隔离（见 P-2） |
| 上行只读查询 | 表现 → 域 | `BattleQueryDispatcher`（复用 `StatHook.Resolve` + `SlipperyHook.Clamp` + `CardBonusHook.GetBonus`）；域内查询 `BattlePerkQuery` | 只读快照，零副作用；本轮引入复用缓冲（见 P-3） |
| 横向状态介入 | 域内部 | `Hook`：`StatHook`/`SettleHook`/`DeathGuardHook` + PerkRules 组（`SlipperyHook`/`FullBlockHook`/`HpDropHook` + 本轮新增 5 个） | 状态经 Hook 介入结算，数值判定与预览同源 |

> `BattlePerkQuery`（`RuntimeData/Actor/Perk/BattlePerkQuery.cs:6`，45 行）与 `BattleQueryDispatcher` **职责不重叠**：前者是域内部类型安全的 `Find<T>`/`Has<T>`/`EnergyCapBonus` 状态查询工具（调用点全在 `GameBattle`），后者是表现层上行只读门面（堆数 / 落点预览 / 伤害 / 格挡）。一内陆一上行，边界清晰，属本轮正向改进。

**两级命令门面**：战斗内命令经 `BattleCommandDispatcher` 入队（只 `Enqueue`，执行在 `RunLoop` 等待态出队后）；跨段整局写操作经 `RunCommandDispatcher` 收口，写域由 `GameRun` 域服务完成（含 `RewardClaimService` 的 `HashSet` 幂等去重与 `Stale`/`PotionSlotsFull` 重试语义）。

### 3.4 六场景阶段（同构零漂移）

`SegmentSceneManager`（298 行）按地图节点类型叠加编排六阶段：先古之民 / 休息 / 战斗 / 宝箱 / 商店 / 事件。每段 = `LifetimeScope`（隔离 DI）+ `Loop/Session`（域侧规则）+ `PresentationBridge`（事实下行 + 命令上发）。7 个 `*LifetimeScope`（含整局根）高度同构：装配期配置体检 → `Parent.Container.Resolve<RunState>()` → 构造 Session/Dispatcher/Loop → `RegisterInstance` + `RegisterComponentInHierarchy` + `RegisterEntryPoint` → `RegisterBuildCallback` 兜底注入游离 `UI_HoverTip`。常驻靠 `RunLifetimeScope` + 叠加场景，无滥用（唯一代码级 `DontDestroyOnLoad` 为 `GameRoot` 活跃载体，见 Z-1）。

### 3.5 本轮新增/改造的关键机制

**① 铁甲战士状态族（14 个 `SO_*` + 14 个 `BP_*` + 5 个 Hook）**
新增状态：壁垒 / 巨像 / 猩红斗篷 / 残忍 / 暗影拥抱 / 恶魔形态 / 紧缚 / 无惧疼痛 / 火焰屏障 / 地狱狂徒 / 炼狱 / 无抽 / 炽焰 / 凶恶。`ConfigData` 侧纯数据（`[CreateAssetMenu]`，少量数值字段）；`RuntimeData` 侧 `sealed` + 构造注入 SO + `Clone()` 走 `WithLayers`；`PerkBaker.cs:25-38` 显式登记全部 14 类型，每个状态均有 Hook / 阶段消费点，无静默失效。`_ => throw` 兜底保留，属既有防漏登记纪律。

**② 五个 PerkRules Hook（`GameBattle/Hook/PerkRules/`）**
| Hook | 职责 | 接入点 | 分派方式 |
| --- | --- | --- | --- |
| `DamageReactHook` | 火焰屏障受击反伤 | `BA_Damage.cs:70`（传 `false,false` 防递归） | `Find<BP_FlameBarrier>` |
| `ExhaustHook` | 暗影拥抱抽牌 / 无惧疼痛格挡 | `BA_Exhaust.cs:23`、`BA_ApplyCardExhaust.cs:24` | 两个 `Find` |
| `PerkApplyHook` | 凶恶给易伤抽牌 | `BA_ApplyPerk.cs:27` | `Find<BP_Vicious>` |
| `DrawHook` | 地狱狂徒自动打出「打击」 | `BA_DrawCard.cs:50` | `Find<BP_Hellraiser>` |
| `CardBonusHook` | 按牌加成（紧缚格挡） | `CardAffixResolver.cs:106` 结算 + `BattleQueryDispatcher.cs:64` 预览 | 硬编码 switch（与 `StatHook` 同构） |

前四个沿用「动作 Execute 内嵌 Check、事件并入收集表」既有范式，无 switch、无上帝类；`CardBonusHook` 的 switch 是小型分派表，新增按牌加成状态需改表，属既有模式的可接受成本。**`DrawHook.cs:23-28` 的嵌套自动出牌直接 `action.Execute(context_)`（见 P-4）。**

**③ 出牌拒绝判定同源（`BP_PlayerTurnActive.TryGetRejectReason:93-105`）**
把「能否打出」与「拒绝原因」合为一次判定（判定顺序即优先级）；表现层 `UI_BattlePopRoot:121-123` 仅订阅 `BE_CardPlayRejected` 后按 enum 映射台词，未复制规则。是「表现层不持业务规则」的正面证据。

**④ 预览复用缓冲（`BattleQueryDispatcher.cs:15-17`）**
新增 `_enemyScratch`/`_aliveBuffer`/`_targetBuffer` 实例字段，`BattleContext.GetAliveEnemies(List)` 重载支持零分配填充；`BattleTargetDirector` foreach 改下标遍历避免接口枚举器装箱。当前调用点（`BattleTargetDirector:77/98`、`UI_HandAim:60`、`UI_PotionGroup:79`）均同帧同步消费，无实发 bug，但生命周期靠注释契约（见 P-3）。

**⑤ 异常隔离（`BattleEventDispatcher.cs:66-76` / `SegmentEventDispatcher.cs:56-66`）**
两处逐字同构的 `InvokeSafely`：`try { await handler_; } catch (Exception) { LogError + LogException; }`。修复「一条演出异常终止域动作链、队列留半截」的真实问题，但边界划到统一分派出口，域反应方（遗物等）异常同样被吞（见 P-2）。

**⑥ 先古遗物子组组件化（`UI_AncientSubGroup.cs`，23 行）**
三个 `[SerializeField]` 引用（`_icon`/`_name`/`_group`）+ `Bind(SO_Ancient)`；替代了 `UI_RelicEncyclopediaPanel` 中 `sub.Find("Title/Icon").GetComponent<Image>()` 等字符串路径耦合，改为模板节点 `GetComponent<UI_AncientSubGroup>()` + `Bind` + `subGroup.Group`（`UI_RelicEncyclopediaPanel.cs:95-103`）。消除反模式、纯展示、不写域。

**⑦ 补间接力修复（`UiTween.cs:15-20` / `UI_CardBattle.cs:357-366,380-384` / `UI_PlayCardZone.cs:52`）**
`KillSlot` 改为「建前先判 `IsActive` 再 Kill」，避免对已被 DOTween 回收的补间再 Kill 导致 activeTweens 越界；出牌入队前 `card_.SettleMotion()` 把入场补间推到终点，使队位补间从静止起算。均操作表现层对象自身补间，非域状态直写。

## 八、不变量核验

逐条核验，10 条主体成立（K2/K3 为域内关注点，P-2 为异常路径例外）：

1. **状态变更只经动作系统**：`BA_*` 是唯一改写战斗状态的入口；`RaiseMaxHp` 经 `Creature` private setter + 通知。`DrawHook` 嵌套出牌直接 Execute 但在队列消费中、动作仍是 `BA_*`（P-4 为序列复制风险，非旁路）。
2. **命令只入队不执行**：表现层经 `*CommandDispatcher` 上发，域侧消费。
3. **失败路径也走事件/返回值**：领奖失败经 `Stale`/`PotionSlotsFull`，战斗失败经 `BE_*`；**例外**：异常路径经 `InvokeSafely` 只记日志不发事件（P-2）。
4. **配置只读一次**：SO 经 `Baker` 烘焙为运行时对象，运行时不回读 SO。
5. **模板/实例必须显式 Clone**：`CM_Runtime.Clone` / `ModifiableStat.Clone` / `BP_*.Clone` / `CA_ApplyPerk.Clone`（本轮补 `_showPerkDescription` 字段）链路完整。
6. **预览与结算同源**：数值判定共用 `StatHook.Resolve` + `SlipperyHook.Clamp` + `CardBonusHook.GetBonus`；**例外**：`PreviewTargets` 落点判定另有副本（P-1），且随机目标预览有意不掷骰。
7. **表现层不持业务规则、不直接篡改域状态**：`UI_RewardPanel` 经门面上报，`UI_*` 视图零域写（测试 DevPanel 除外）；拒绝原因判定在域侧一次完成。
8. **整局状态由整局层持有、表现只读**：`RunState`（含 `DrawLedger`）持有进度，表现 `[Inject]` 只读。
9. **六阶段同构零漂移**：7 个 `LifetimeScope` 同模板 + `Loop/Session` + `PresentationBridge`。
10. **无 `DontDestroyOnLoad` 滥用**：唯一代码命中为 `UI_SingletonObject`，是 `GameRoot` 跨场景常驻的活跃载体，非死代码。
