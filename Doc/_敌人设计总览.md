# 敌人系统总览（Slay the Spire 2 · 单人模式）

> **数据来源**：反编译工程 `src/Core/Models/Monsters/*.cs`（121 个 `MonsterModel` 子类）、
> `src/Core/Models/Encounters/*.cs`（88 个 `EncounterModel`）、`src/Core/Models/Acts/*.cs`（4 个 `ActModel`）、
> `src/Core/MonsterMoves/`（意图与行动状态机）、`src/Core/Models/MonsterModel.cs`、
> `src/Core/Entities/Creatures/Creature.cs`，中文名取自 `localization/zhs/{monsters,encounters,intents,powers,ascension,acts}.json`。
>
> **口径**：按用户约定只看单人模式，剔除联机/同步层。`ScaleHpForMultiplayer` 与 `MultiplayerScalingModel` 在 1 人时不生效。
> 表中数值均为**无进阶（进阶 0）基准值**；`a–b` 为进场随机区间，`（固定）` 表示 `MaxInitialHp == MinInitialHp`。
> 进阶 8 / 9 的变化见第九节对照表。招式名优先用中文本地化，缺失时保留英文状态 ID。

## 二、敌人如何运转（框架层）

### 2.1 模型两态与实例化

与卡牌一致，敌人是「canonical / mutable」两态：`ModelDb` 注册的是只读原型，进战斗时 `ToMutable()` 克隆，
`EncounterModel.GenerateMonsters()` 返回 `(MonsterModel, slotName?)` 元组数组（可带槽位名，用于多单位站位）。
`Creature` 持有 mutable `MonsterModel`；`MonsterModel.Creature` 反指。战斗结束随牌堆一起丢弃，不跨战斗持久化。

- 入场时 `AfterAddedToRoom()` 挂初始 Power（本文称「自带特点」）；`BeforeRemovedFromRoom()` 做离场清理。
- `MonsterModel` 可实现 Hook（`AfterCurrentHpChanged` / `BeforeDeath` / `BeforeRemovedFromRoom` 等）实现阶段切换、联动死亡等。

### 2.2 HP 生成：区间随机 + 同场去重

`Creature` 构造时先把 `MaxHp = CurrentHp = MaxInitialHp`；随后 `CombatState` 调用
`SetUniqueMonsterHpValue(creaturesOnSide, RunState.Rng.Niche)`：

1. 在 `[MinInitialHp, MaxInitialHp]` 内取值；
2. 从候选集合里**排除同侧已有生物的 MaxHp**；
3. 候选耗尽才回退为纯随机。

因此「两只同类怪」的血量必然不同（例如一对啃咬机 60 / 64），这是为辨识度服务的设计，而非纯随机波动。

### 2.3 行动状态机

`GenerateMoveStateMachine()` 返回 `MonsterMoveStateMachine`，三类节点：

| 节点 | 作用 |
| --- | --- |
| `MoveState` | 实际一招：`(stateId, onPerform, params AbstractIntent[])`；`FollowUpState` 指向后继，`MustPerformOnceBeforeTransitioning` 保证至少执行一次才允许切走 |
| `RandomBranchState` | 带权随机分派；`AddBranch(state, weight / cooldown / MoveRepeatType)`，权重可为 `Func<float>`（如按回合奇偶、是否可召唤动态调整） |
| `ConditionalBranchState` | 按 `Func<bool>` 顺序取第一个为真的分支（半血、门扉存活、是否蓄力等） |

`MoveRepeatType` 四档：`CanRepeatForever` / `CanRepeatXTimes` / `CannotRepeat`（禁止连续重复）/ `UseOnlyOnce`（全场只一次）。
`StateLog` 记录已执行过的招，供重复约束与冷却判定。全工程 **23** 个敌人用随机分支、**16** 个用条件分支。

`SetMoveImmediate(state, forceTransition)` 允许外部强制切招（击晕、复活、阶段切换后立即换意图），并同步刷新 UI。
`RollMove()` 使用独立的 `RunRng.MonsterAi` 随机流——敌人 AI 与卡牌/RNG 互不干扰，便于存档复现。

### 2.4 意图系统

`IntentType` 共 15 类，实际使用 14 类（`UnknownIntent` 未见使用）：

| 意图 | 中文 | 显示 | 出现次数 |
| --- | --- | --- | --- |
| `SingleAttackIntent` | 攻势 | 单次伤害数值 | 164 |
| `MultiAttackIntent` | 攻势 | `伤害×次数` | 54 |
| `BuffIntent` | 强化 | 强化图标 | 77 |
| `DebuffIntent` / `strong` | 策略 | 弱化 / 强弱化 | 41 |
| `DefendIntent` | 守势 | 格挡图标 | 24 |
| `StatusIntent` | 策略 | 状态牌张数 | 18 |
| `CardDebuffIntent` | 恶意 | 卡牌侵蚀 | 4 |
| `StunIntent` | 击晕 | 下回合无法行动 | 9 |
| `SleepIntent` | 沉睡 | 本回合无行动 | 5 |
| `HealIntent` | 回复 | 回复 | 4 |
| `SummonIntent` | 召唤 | 召唤怪物 | 8 |
| `EscapeIntent` | 懦弱 | 逃跑 | 3 |
| `DeathBlowIntent` | 濒死一击 | 摧毁前造成伤害 | 2 |
| `HiddenIntent` | — | 隐藏（假人/占位） | 3 |

关键设计：**一个 MoveState 可携带多个意图**，`Intents` 是数组，UI 同时显示多个图标
（例：`攻 12 + 守`、`弱化 + 回复 + 强化`）。`AttackIntent.GetSingleDamage()` 调用
`Hook.ModifyDamage(..., ValueProp.Move, ...)`，与实战伤害走同一修正管线，因此意图显示的数值不会与实际结算脱节。
攻击图标按总伤害分 5 档（<5 / <10 / <20 / <40 / ≥40），并驱动对应攻击动画档位。

### 2.5 回合时序

```
SetUpForCombat()          生成状态机、标记 SpawnedThisTurn
      ↓
RollMove(targets)         状态机选下一招 → NextMove
      ↓
UI 读 NextMove.Intents    显示意图图标 / 数值 / 悬浮说明
      ↓
PerformMove()             await 命令序列（伤害 / Power / 格挡 / 塞牌 / 召唤 / 治疗 / 逃跑）
      ↓
OnMovePerformed()         写 StateLog → MonsterPerformedMoveEntry 进战斗历史
```

`PerformMove()` 前后各有 `Cmd.CustomScaledWait`（0.1/0.2 与 0.1/0.4），用于对齐动画与 VFX；
执行体是 `Func<IReadOnlyList<Creature>, Task>`，目标恒为 `CombatState.PlayerCreatures`。

### 2.6 难度修正：进阶而非幕缩放

`AscensionLevel` 共 11 档（0–10），与敌人相关的三档：

| 进阶 | 中文 | 效果 |
| --- | --- | --- |
| 8 `ToughEnemies` | 强韧敌人 | `MinInitialHp` / `MaxInitialHp` 提高（普通 +1~3，精英 +4~10，Boss +10~23），部分格挡/覆甲层数提高 |
| 9 `DeadlyEnemies` | 致命敌人 | 招式伤害提高（通常 +1~+3，重击 +3~+5），少量次数/力量成长同步提高 |
| 10 `DoubleBoss` | 双重 Boss | 第 3 幕末尾同时打两个 Boss，不改单怪数值 |

统一通过 `AscensionHelper.GetValueIfAscension(level, high, low)` 内联在属性里，**没有独立的难度数据表**。
进阶 1「精英蜂拥」只提高精英房出现频率。

## 三、数值体系与设计曲线

| 分层 | 样本 | HP 范围 | 中位 | 均值 | 典型单招伤害 |
| --- | --- | --- | --- | --- | --- |
| 普通 / 弱战 | 70 | 6–300 | **49** | 67.9 | 3–16 |
| 精英 | 14 | 17–300 | **97** | 121.3 | 9–35 |
| 首领 | 15 | 58–489 | **211** | 245.8 | 11–45 |

（按「至少出现在一场对应 RoomType 遭遇」的怪物模型统计，排除 9999 血占位；含随从单位，故 Boss 层含 58 HP 的同族信徒。）

- **招式数**：3 招最普遍（37 个模型），其次 1 招（23）、2 招（22）、4 招（21）、5 招（10）；最多 8 招（瀑布巨兽、实验体）。
- **意图配比**：攻击类 218 / 强化 77 / 弱化 41 / 守 24 / 状态牌 18 / 其它 38。约 **2/3 的招式带攻击意图**，强化是第二高频动作。
- **多段攻击**：段数 2–8，单段 1–9 点。低单段 × 高段数（追踪手 1×8、蜂群术士 3×7、高塔炮手 3×5）用于压制单次高格挡、放大力量收益；高单段（处决 15、魔法炸弹 35、大扑 45）用于逼出防御资源。
- **状态牌投放量**：1–10 张；最多是史莱姆狂战士一次塞 10 张黏液。投放位置分手牌（灼伤/剧毒）、抽牌堆（随机位置）、弃牌堆三类，对应即时干扰与延迟干扰。
- **遭遇编成**：单只 53 场、2 只 19 场、3 只 11 场、4 只 4 场。多单位战常配「爪牙」（领袖死则弃战）或「互相复活」机制，把编成变成机制而非单纯堆血量。

## 五、逐敌数值与意图（121 个模型）

**读表说明**

- 「行动循环」列每招写作 `招式名〔意图 · 数值〕＋附带效果`；`攻 8×2` = 8 点伤害命中 2 次，`守` = 获得格挡，
  `状态牌×3` = 向牌堆塞 3 张状态牌，`强化` / `弱化` = 自身增益 / 玩家减益，`濒死一击` = 被摧毁前反击。
- `＋` 后是该招的**附加结算**：力量 / 虚弱 / 脆弱 / 易伤 / 格挡 / 状态牌 / 召唤 / 治疗 / 自毁等，
  这些不是意图图标，但属于该招的实际效果，是判断威胁的关键。
- 「自带 / 附加特点」列入场即挂载的 Power（中文名 + 层数）与关键 Hook override；详见第七、八节。
- 表格按幕 → 房间类型分组；随从单位归入其所属遭遇的房间类型（例如同族信徒归在「首领」组）。
  跨幕共用的模型会在两幕各出现一行（`CubexConstruct`、`PunchConstruct`），故表格共 123 行、覆盖 121 个唯一模型。

> 说明：`沉睡`、`门扉复活`、`寄生物`、`意外` 的本地化描述仍是占位文本（`AsleepPower` 的 description 甚至直接写着 TODO），实际行为以源码为准：
>
> - `AsleepPower`（沉睡）：Counter 层数，回合末递减；**吃到未格挡伤害立即击晕并切到苏醒招**；层数归零自动醒。并非免疫。
> - `DoorRevivalPower`（门扉复活）：`BeforeDeath` / `AfterDeath` 阻止移除，由门扉缔造者 `DoRevive()` 重设 MaxHp 并回满。
> - `InfestedPower`（寄生物）：死亡时召唤一只起始眩晕的扭动虫，并 `ShouldStopCombatFromEnding()` 阻止战斗结束。
> - `SurprisePower`（意外）：地精佣兵死亡时召唤卑鄙地精 + 胖地精，并把偷来的金币以 `HeistPower` 转移到胖地精身上——**打死不算完，还得追赃**。

## 十、设计规律与自研借鉴

### 10.1 可归纳的规律

1. **全公开意图 + 受约束的随机**。玩家永远知道下一招是什么（数值也经同一修正管线计算），
   随机性只体现在「下一招从哪个分支抽」；`CannotRepeat` / `UseOnlyOnce` / 冷却 / 动态权重避免连续同招与死角。
   这是「可计算的风险」而非「不可预测的惩罚」。
2. **3 招循环是骨架**。37 个模型恰好 3 个 MoveState，常见形态是「小攻击 → 大攻击 → 强化/防御」或「攻击 → 状态 → 攻击」；
   首领才扩展到 5–8 招并引入条件分支（半血、复活、蓄力层数）。
3. **高伤必配窗口**。几乎所有 25+ 的招式前面都有蓄力、沉睡、格挡或其它可预判节点；
   反之，带 `DefendIntent` 的招式常同时造成伤害，避免纯防守回合变成免费输出。
4. **机制密度随层级上升**：普通战 1–2 个机制（多为成长 + 状态牌），精英 2–3 个（加专属减伤/控制），
   首领 3–5 个（复活、编成联动、阶段切换、倒计时）。
5. **不做幕间数值膨胀**。同一套数值规则贯穿 3 幕，难度靠遭遇池替换 + 进阶等级整体修正，
   便于平衡与回归测试；`AscensionHelper` 内联在属性里，没有第二份难度表要同步。

### 10.2 若要复刻，按依赖顺序实施

| 顺序 | 层 | 内容 | 依赖 |
| --- | --- | --- | --- |
| 1 | 数据层 | `MonsterModel`（HP 区间、招式表、入场 Power、Hook）、`EncounterModel`（编成、槽位、房间类型、弱战标记） | 无 |
| 2 | 状态机 | `MoveState` + 随机/条件分支 + `MoveRepeatType` + `StateLog` + 独立 AI 随机流 | 1 |
| 3 | 伤害/Power 管线 | `ModifyDamage` / `ModifyBlock` 分阶段修正、`PowerModel` 挂载与事件 | 1 |
| 4 | 意图层 | 14 类意图、多意图并列显示、攻击分档图标；**数值必须调用第 3 步的修正管线** | 2、3 |
| 5 | 招式执行 | `DamageCmd` / `PowerCmd` / `CardPileCmd` / `CreatureCmd.{GainBlock,Heal,Add,Stun,Kill,Escape}` 的 async 命令序列 | 3 |
| 6 | 进阶与幕池 | `GetValueIfAscension` 内联属性、按幕枚举遭遇、弱战/精英/首领房分配 | 1 |
| 7 | 表现层 | 意图节点、动作动画触发、VFX 即发即弃、`CustomScaledWait` 对齐时长 | 4、5 |

**容易返工的三处依赖**：召唤系统依赖「槽位」概念（否则多单位站位无法表达）；
复活/多阶段依赖 `BeforeDeath` / `AfterCurrentHpChanged` 钩子（否则无法在致死时改写结果）；
朝向轴依赖玩家朝向状态（否则「背后攻击 +50%」无处取值）。这三项应在第 1 步的数据契约里预留。
