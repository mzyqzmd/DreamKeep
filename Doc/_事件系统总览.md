# 《杀戮尖塔 2》(Slay the Spire 2) 事件系统总览

> 基于本地工程 `src/Core/**` 逐文件扫描生成，覆盖 **68 个事件模型**（`src/Core/Models/Events/*.cs`）、4 个 Act 事件池与全部布局/同步机制。
> 中文主题名为按代码内容推断的设计语义；机制描述均来自源码，未做估算。
> 统计口径：含 2 个占位废弃类（`DeprecatedEvent` / `DeprecatedAncientEvent`）与 1 个测试 Mock（`Mocks/MockEventModel.cs`）。
> 分析范围按项目约定**排除联机/同步层**（`EventSynchronizer`、`SharedEventOption*` 投票消息等），只保留单人版逻辑。

---

## 0. 结论摘要

1. **68 个事件模型 = 57 个地图池普通事件 + 8 个远古事件 + 1 个通关事件 + 2 个废弃占位**。普通事件按 Act 分发：第一幕 13 / 第二幕 10 / 第三幕 10 / 第四幕 7，另有 18 个共享池全 Act 通用（`SunkenStatue` 是唯一跨两幕重复出现的事件）。
2. **分类是五维正交的**：① Act 池（发放渠道）② `EventLayoutType` 布局（Default/Combat/Ancient/Custom）③ 选项结构（静态二选一 / 动态条件生成 / 多轮循环）④ 纪元解锁（Epoch 门控 5 个事件）⑤ 联机共享（7 个，单机版直接忽略）。
3. **事件 = 数据驱动的"选项状态机"，不是特例系统**：所有事件共用 `EventModel` 基类，子类只需实现 `GenerateInitialOptions()` 返回 `EventOption` 列表，每个选项挂一个 `Func<Task>` 回调；页面推进靠 `SetEventState(描述, 选项)` 换页，文案变量靠 `DynamicVars` + `CalculateVars()` 注入。
4. **最独特的五个机制**：① 远古事件对话系统（按角色 × 拜访次数分流台词+音效，§4.1）；② 事件内战斗且战后可回到事件（`EnterCombatWithoutExitingEvent` + `Resume`，§4.2）；③ 循环赌局/多轮递进状态机（无尽传送带、真理石板 5 轮致死特判，§4.3）；④ 自定义小游戏节点（水晶球，§4.4）；⑤ 通关演出事件 TheArchitect（复用战斗房间当舞台，§4.5）。
5. **复刻建议**：先抄"基类 + EventOption + DynamicVars + IsAllowed 去重"这条管道（约 600 行核心），再挑 T1 级的 25 个纯数值交换事件铺量；循环类（T2）挑 2~3 个；事件内战斗（T3）实现 1 个通用入口即可解锁 5 个事件；小游戏/演出类（T4）单人复刻性价比最低。

## 1. 系统分层：事件在代码里的位置

| 层 | 类型 / 文件 | 职责 |
|---|---|---|
| 模型基类 | `EventModel : AbstractModel`（`Models/EventModel.cs`，516 行） | 选项生成、页面状态机、动态变量、事件内战斗入口；canonical/mutable 两态与卡牌/遗物完全一致 |
| 远古子基类 | `AncientEventModel : EventModel`（`Models/AncientEventModel.cs`，245 行） | 对话集、按拜访次数/角色分流选项、开局满血治疗（Neow 特例置 0 血） |
| 选项类 | `EventOption`（`Events/EventOption.cs`，157 行） | 标题/描述/悬停提示/锁定态/致死预告（`ThatDoesDamage`）/历史记录开关；`Chosen()` 触发回调 |
| 房间类 | `EventRoom : AbstractRoom`（`Rooms/EventRoom.cs`，127 行） | 进入时 `BeginEvent` → 建 `NEventRoom` UI；退出时全体 `EnsureCleanup()`；战斗归来时 `Resume` 重建 UI |
| 布局枚举 | `EventLayoutType`（`Events/EventLayoutType.cs`） | Default / Combat / Ancient / Custom 四态，决定加载哪个场景 |
| UI 节点 | `NEventRoom`、`NEventLayout`、`NEventOptionButton`、`NAncientEventLayout`、`NCombatEventLayout`、`ICustomEventNode`（`Nodes/Events/`） | 选项按钮列表、对话气泡、自定义事件节点契约 |
| 表现资源 | `scenes/events/`（3 布局 + 2 Custom + 10 远古背景）、`images/events/<ID>.png` 立绘、`vfx/events/<ID>_vfx` | 按 ID 小写寻址，与模型解耦 |
| 本地化 | `localization/*/events.json`（774 键）、`ancients.json` | 键格式 `<EVENT>.pages.<PAGE>.description` / `.options.<NAME>.{title,description}` |

**关键契约**：
- 事件模型 `ShouldReceiveCombatHooks => false`——事件本体不参与战斗钩子链，但可通过遗物/药水间接影响。
- 选项回调是 `async Task`，可以 `await` 任何命令（治疗/伤害/抽卡/发奖），天然获得"播完动画再翻页"的节奏。
- 每个事件有独立 `Rng`（种子 = RunState.Rng.Seed + NetId + 事件 ID 哈希），保证同种子同结果。

### 2.3 按选项结构

| 结构 | 实现手法 | 代表事件 |
|---|---|---|
| 静态二选一/三选一 | `GenerateInitialOptions()` 直接返回固定 `EventOption` | ThisOrThat、HungryForMushrooms、DoorsOfLightAndDark 等约 30 个 |
| 动态条件生成 | 选项 handler 传 `null` → `IsLocked=true` 显示 `*_LOCKED` 文案；或按持有物/牌组状态增删选项 | TeaMaster、StoneOfAllTime、RelicTrader、SelfHelpBook、WoodCarvings |
| 多页多轮循环 | 回调里再调 `SetEventState()` 换页重建选项，配合计数器 | EndlessConveyor（无限循环直到钱不够）、TabletOfTruth（5 轮递增加死）、SlipperyBridge（撑住次数 ≥7 后走 LOOP 文案）、AbyssalBaths（浸泡 9 级）、ColossalFlower（挖掘 3 层）、TinkerTime（三轮选项链定制卡牌） |

| 无选项（全 UI 驱动） | 覆写 `LayoutType=Custom` 自绘交互 | CrystalSphere、FakeMerchant |

## 4. 独特机制及实现方式

### 4.1 远古事件对话系统（8 个事件共用）

`AncientEventModel.DefineDialogues()` 返回 `AncientDialogueSet`，本地化表 `ancients.json` 的键结构 `DARV.talk.<角色|ANY>.<拜访序号>-<行号>.{ancient,char,next}`：
- `FirstVisitEverDialogue`：整个存档第一次见面（如 Neow 的开场白）。
- `CharacterDialogues`：按角色（Ironclad/Silent/Defect/Necrobinder/Regent）分组，`VisitIndex` 0/1/4 区分第几次见，每条 `AncientDialogue` 可带多段 SFX 路径（`event:/sfx/npcs/darv/*`）。
- `AgnosticDialogues`：通用兜底；`AnyCharacterDialogueBlacklist` 可排除无语音角色（Tezcatara 拉黑 Defect）。
- 选项走 `AllPossibleOptions` 全集声明 + `RelicOption<T>()` 快捷构造；`Done()` 收尾时把"每个选项是否被选"写进地图历史（`AncientChoiceHistoryEntry`）。
- 进门即治疗到满血（`BeforeEventStarted`，Neow 特例先把 HP 置 0 再治疗）； ascension "WearyTraveler" 治疗量 ×0.8。
- 存档侧：远古事件完成后整个房间标记 `IsPreFinished` 并即时存档，读档直接进 DONE 页（`EventRoom.OnEventStateChanged`）。

**复刻建议**：内核（洗牌抽遗物+条件解锁）可直接抄；对话系统可降级为"按拜访次数取 1~3 段静态文本"，省掉角色分流与音效。

### 4.2 事件内战斗 + 战后回到事件（5 个事件）

`EventModel.EnterCombatWithoutExitingEvent(encounter, extraRewards, shouldResumeAfterCombat)`（`EventModel.cs:458-491`）：
- 要求 `IsShared`（设计上用于共享事件，单人可去掉该断言）；
- 构造 `CombatRoom` 并设 `ShouldCreateCombat = (LayoutType != Combat)`、`ShouldResumeParentEventAfterCombat`、`ParentEventId`，经 `RunManager.EnterRoomWithoutExitingCurrentRoom` 压栈进入；
- 战斗结束出栈后 `EventRoom.Resume()` 重建 `NEventRoom`，模型侧由事件自己覆写 `Resume(AbstractRoom)` 发奖（BattlewornDummy 按木桩档位发药水/升级/遗物）；
- `LayoutType == Combat` 的三个事件（PunchOff、TheLanternKey、TheArchitect）不走压栈，而是 `GenerateInternalCombatState()` 预生成战斗状态直接复用战斗场景当地图。
- 另一模式是"战后不回来"（`shouldResumeAfterCombat: false`）：DenseVegetation 休息后强制开战、FakeMerchant 揭穿后店内开战、TheLanternKey 私藏钥匙开战。

**复刻建议**：一个"事件房间 ↔ 战斗房间互相压栈"的房间栈即可解锁全部 5 个，是本系统性价比最高的通用机制。

### 4.3 循环赌局与多轮递进状态机（6 个事件）

- **EndlessConveyor**：`Dish` record struct 带 `weight`，`RollDish()` 按权重抽池；池成员按状态条件动态增减（有空药水槽/不满血/抓取>1 次才入池）；`_lastDishId` 防连续重复；`NumOfGrabs % 5 == 0` 强制 FeedingFrenzy；钱不够把抓取选项换成 LOCKED。文案变量 `CurrentDishTitle/LastDishTitle` 动态回填。
- **TabletOfTruth**：`DecipherCount` 计数 + 代价表 3/6/12/(MaxHp-1)；代价 ≥ 当前上限时 `ThatWillKillPlayerIf` 把选项标为致死按钮；`LoseMaxHpAndUpgrade` 里 hp≥MaxHp 时先扣到 1 再 `CreatureCmd.Kill` 特判；第 5 轮遍历升级全部可升级卡（`CardPreviewStyle.MessyLayout` 连播）。
- **SlipperyBridge**：`GetHoldOnSuffix()` 在撑住 ≥7 次后切换到 "LOOP" 键，实现"无限循环"叙事；随机挑牌过滤 `IsRemovable` 且避开上一张。
- **AbyssalBaths / ColossalFlower**：层级递进 + 动态改写 `DynamicVars["HpLoss"].BaseValue` / 多层奖励表。
- 公共手法：回调内再次 `SetEventState()` 换页重建选项列表，UI（`NEventLayout`）订阅 `StateChanged` 自动重绘。

### 4.4 自定义小游戏与自绘 UI（2 个事件）

- **CrystalSphere**：`LayoutType.Custom` + `ICustomEventNode.Initialize(event)`，场景 `scenes/events/custom/crystal_sphere/`，`CrystalSphereMinigame.PlayMinigame()` 跑 3/6 回合预览战斗的弹珠小游戏；`IsDeterministic => false` 显式声明不走校验和。
- **FakeMerchant**：`custom/fake_merchant.tscn` + `MerchantInventory`（9 个 Fake 假遗物洗牌抽 6 上架），复用商人节点体系；隐藏交互"扔 FoulPotion"→ `FoulPotionThrown()` 转店内开战。

### 4.5 通关演出事件 TheArchitect

`LayoutType.Combat` 但 `CanonicalEncounter = TheArchitectEventEncounter`：Boss 战后由 `RunManager.cs:1001` 直接 `new EventRoom(ModelDb.Event<TheArchitect>())` 进入，把战斗房间当舞台：
- `OnRoomEnter` 从 `NCombatRoom.Instance.CreatureNodes` 抓建筑师生物节点；
- 台词用 `TalkCmd.Play(line, speaker, double.MaxValue)` 挂 `NSpeechBubbleVfx` 到生物身上，`AncientDialogueSpeaker` 区分建筑师/玩家；每行对话生成一个"继续"选项推进状态机；
- `ScoreUtility.CalculateScore` 算分后 `DivideWildly` 把总分随机拆成多个伤害数字，配角色攻击动画 + 专属 Vfx + 伤害飘字 + 分级震屏；`AnimArchitectAttackIfNecessary` 按 ArchitectAttackers 决定建筑师是否反击；
- 结束选项 `WinRun` 结算通关。

## 5. 单人版复刻路线图（按性价比排序）

### T0 基础设施（必须先做，约 600 行核心）

1. `EventModel` 基类：`GenerateInitialOptions()` 抽象 + `SetEventState(描述, 选项)` 换页 + `StateChanged` 事件 + `DynamicVars`（Gold/HpLoss/Heal/StringVar 五类）+ `CalculateVars()` 钩子 + `IsAllowed(runState)` 准入 + `Rng`（按 ID 哈希播种）+ `BeginEvent/EnsureCleanup` 生命周期。
2. `EventOption`：handler 回调 + `IsLocked`（null handler）+ 致死预告 + 悬停提示。
3. `EventRoom`：进房 `BeginEvent` → 建 UI；出房 `EnsureCleanup`；存档 `IsPreFinished`。
4. 事件池：每幕一个列表 + 共享列表，洗牌进 RoomSet；抽取时跳过 `IsAllowed=false` 与已访问 ID。
5. 文案表：`<EVENT>.pages.<PAGE>.{description, options.*}` JSON 结构（774 键的体量主要靠复制粘贴）。

### T1 纯数值交换事件（约 25 个，1~2 周可铺完）

优先级：ThisOrThat、TrashHeap、HungryForMushrooms、SunkenStatue、SunkenTreasury、UnrestSite、Wellspring、WhisperingHollow、SpiritGrafter、DoorsOfLightAndDark、Amalgamator、AromaOfChaos、Bugslayer、ByrdonisNest、DrowningBeacon、InfestedAutomaton、LostWisp、LuminousChoir、MorphicGrove、PotionCourier、ZenWeaver、TeaMaster、RoundTeaParty、TheLegendsWereTrue、BrainLeech。
共同点：只有"选项 → 命令（GainGold/GainMaxHp/Damage/ObtainRelic/AddCard/RemoveCard）→ 换完成页"，无自绘 UI。

### T2 多页/循环状态机（挑 3~4 个）

EndlessConveyor（循环赌局样板）、TabletOfTruth（递进代价+致死特判）、SlipperyBridge（无限循环叙事）、AbyssalBaths（层级递进）。做法都是"回调里再 SetEventState + 计数器"，T0 支持好后每个约 100~150 行。

### T3 事件内战斗（1 个通用入口解锁 5 个事件）

实现"事件房间 ↔ 战斗房间压栈 + Resume 回事件发奖"：BattlewornDummy（战后台式发奖）、TheLanternKey（还钱还是打）、DenseVegetation（休息后强制打）、FakeMerchant（揭穿后打）、PunchOff（Combat 布局，可最后做）。

### T4 低性价比 / 建议砍掉或重度简化

- CrystalSphere：完整弹珠小游戏，工作量与一个独立小游戏相当——可改为"花金币直接看 3 场未来战斗的敌人配置"文本版。
- Trial / TinkerTime：随机叙事模板与参数化造卡很出彩，但依赖嵌套 LocString 与大量分支结局——单人版可各保留"单模板单结局"的最小版。
- TheArchitect：通关演出是纯表现层，可用"一段文字 + 一个通关按钮"替代。
- 远古对话系统：保留"洗牌抽遗物 + 条件解锁"内核（8 个事件直接可用），对话降级为按拜访次数取静态文本。
- WelcomeToWongos 的元积分徽章：需要存档级元进度，初版可砍成纯商店。

## 6. 自研借鉴要点（一句话版）

1. 事件 = 选项状态机：基类管页面/变量/生命周期，子类只管"返回选项列表"，新增一个事件 ≈ 新增一个 100 行的类 + 一段 JSON。
2. `EventOption` 的 handler 传 null 即自动变 LOCKED 占位——条件选项零成本。
3. `DynamicVars` + `CalculateVars()` 让文案数值随 Rng/玩家状态动，避免硬编码字符串。
4. 事件与战斗通过"房间压栈"互通，`shouldResumeAfterCombat` 一个布尔决定战后回不回来——比"事件里嵌一场假战斗"干净得多。
5. 抽取去重（IsAllowed + VisitedEventIds）与 Epoch 解锁门控都做在池子侧，事件模型本身无感知。
