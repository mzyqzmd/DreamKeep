> 定位：本文是**自研事件的内容设计**，不含代码。

## 0. 一页速览

- **13 则事件** = 12 则常规 + 1 则隐藏（集齐 3 枚记忆碎片才出现）。
- **三条自有机制**：梦境浓度（整局倾向）、记忆碎片（跨事件收集）、梦境侵蚀（不致死代价）。
- **一条硬边界**：卡牌成长只用「加入 / 移除 / 升级」三种原子操作，**不做附魔、变换、事件内战斗**——这三样都是独立系统，事件不该成为它们的第一个入口。
- **分三期落地**：P0 只需现有 API（金币 / 回血 / 侵蚀 / 移除卡 / 升级卡），P1 补「上限可改、药水可发」，P2 补「遗物池、碎片记录、浓度门控」。

## 1. 设计口径

### 1.1 借什么，不借什么

| 决定 | 内容 | 理由 |
|---|---|---|
| 借 | 选项状态机（回调里换页重建选项） | 一条管道承载全部事件，新事件≈一个数据资产 + 一段文案 |
| 借 | 锁定选项占位（不可选但可见，附一句原因） | 让玩家看见「差一点」，是事件的主要张力来源 |
| 借 | 动态变量（文案里的数值/名字由运行时填） | 避免 774 条硬编码文案 |
| 借 | 池侧去重 + 条件准入 | 事件本体不需要知道自己会不会出现 |
| 不借 | 卡牌附魔（Sown / Sharp / Steady…） | 本工程无附魔系统，且附魔会与 `UD_*` 升级补丁的语义打架 |
| 不借 | 卡牌变换（随机换一张同稀有度卡） | 需要「卡池按稀有度分桶」，当前只有 9 张卡，随机换等于随机删卡 |
| 不借 | 事件内战斗（压栈回事件） | 房间栈未落地，属另一个系统；首批不做，见 §8 P3 |
| 不借 | 致死代价与致死预告 | 世界观不允许（见 §2.3），顺带省掉整块 UI |
| 不借 | 自定义小游戏 / 元进度积分 | 单人毕设性价比最低 |

### 1.2 当前局面基线（实测自工程）

| 项 | 现状 | 出处 |
|---|---|---|
| 生命 | 80 | `_Data/Actor/Player.asset` |
| 金币 | 99，**零消费出口** | 同上 / README 待办 |
| 起始卡组 | **9 张**（打击、格挡、痛击、剑柄打击、飞剑回旋镖、上勾拳、恶毒、被遗忘的仪式、伤口） | `_startDeck` 9 条引用，含 1 张诅咒 |
| 起始遗物 | **9 件 = 现有全部遗物** | `_startRelics` 9 条，`_Data/Relic` 共 9 件 |
| 起始药水 | 2 瓶（共 8 种），3 槽 | `_startPotions` / `Player.PotionSlotCount` |
| 战斗节奏 | 3 能量、每回合抽 5 | `Player.asset` |
| 伤害基准 | 打击 6 / 痛击 8 / 剑柄 9 / 上勾拳 13 / 飞剑 3×3 | 卡资产 |
| 敌人 | 树枝史莱姆 30、小啃兽 46 | 敌人资产 |
| 层数 | `RunState.Floor` 从 1 起；弱怪池限前 3 层 | `RunState` / `SO_MonsterPool.WeakFloorLimit` |

**由基线推出的四条硬约束：**

1. **牌组只有 9 张** → 「移除 1 张」= 删掉 11% 的牌组，是最重的代价之一；一则事件里最多移除 1 张，移除 2 张只出现在深层且必须附带大奖励。
2. **遗物已全持有** → 任何「获得遗物」在跑图与遗物池落地前都无法成立。P0/P1 一律改用金币、药水、上限替代，P2 再接遗物（见 §8）。
3. **金币没有出口** → 首批里必须至少有一个「花金币」的事件，否则金币奖励毫无意义。E06 就是为这件事设计的（目前唯一的金币回收点）。
4. **以上全部是演示配置** → 跑图、商店、遗物池落地后，本文所有数值都要按真实牌组规模重标一遍（§5 给出换算口径）。

### 1.3 五条硬规则

1. **三选二页**：一则事件最多 3 个选项、最多 2 页（循环事件在同一页刷新，不翻页）。控制单次阅读量，也规避「事件越写越长」。
2. **侵蚀不致死**：任何事件代价最多把生命扣到 1，不会再低（§2.3）。
3. **只用三种卡牌操作**：加入、移除、升级。不新增第四种。
4. **代价写在选项上**：按钮副标题直接写「生命 -8」「上限 -5」「金币 -25」，不藏在正文里。
5. **文案规范**：第二人称、每页 ≤ 90 字、不用感叹号、不解释机制（让玩家自己看出来）。

## 2. 三条自有机制

### 2.1 梦境浓度（Dream Density）

整局一条 0~8 的暗线，起点 0。**它是「你这一路怎么选的」的记账本**，不是当场可兑换的资源。

| 行为 | 浓度变化 |
|---|---|
| 拿走不该拿的东西、听不该听的话、往更深的梦里走 | +1 ~ +2 |
| 归还、献出、转身、替别人做完一件事 | −1 ~ −3 |

**它管三件事：**

1. **看得见哪些选项**：部分选项要浓度达标才出现（E01 的「应它一声」≥3、E03 的「门缝」≥3、E12 的「走进镜子」≥5）。
2. **抽得到哪些事件**：深梦池（E10~E12）要求浓度 ≥4 才进入抽取队列。
3. **门开哪一扇**：E11 的选项完全由浓度决定（≤3 / 4~5 / ≥6 三档）。

**P3 才进战斗**（浓度 ≥6 时敌人开局多 1 层力量之类）。首批刻意不接战斗：那需要 `BattleSetup` 读整局状态，属另一条改动线，先让浓度在事件层跑通、被玩家感知，再决定要不要污染战斗。

**显示**：顶栏金币旁加一个「雾」图标 + 数字，悬停气泡写「梦境浓度：越高越难醒」。`UI_TopInfoBar` 目前是空壳字段，正好一起做（可选，不阻塞）。

### 2.2 记忆碎片（Memory Shard）

整局 0~3 枚的收集品，不占卡位、不占遗物位、不影响战斗数值。

- **来源（本批共 4 处）**：E01 倾听（最多 2）、E05 过桥（1）、E06 抽奖池（低权重 1）、E10 挖开碑（2）。
- **用途（唯一）**：集满 3 枚后，隐藏事件 E13「回声」进入抽取队列；在 E13 里可以**兑现**（大奖励）、**保留**（什么都不发生）、或**忘掉**（换另一种奖励）。
- **设计意图**：给「事件」这条线一个横贯整局的记忆点。STS 的事件彼此孤立，DreamKeep 用 3 枚碎片把它们串成一条支线，成本极低（一个 int + 一个来源列表），回报是玩家会为了凑齐第三枚去做一次亏本选择。

### 2.3 梦境侵蚀（Erosion）

事件里的一切生命代价统称「侵蚀」，取自世界观——梦魇不杀人，只会让你迷失。

**规则：侵蚀不吃格挡（局外没有格挡）、不吃任何减伤、不会致死，最低保留 1 点生命。**

三个理由：

1. **叙事一致**：守梦人死在梦里 = 醒来，本局结束。事件里被扣死会让「重来」变成惩罚，与「每次力竭都在浅梦重新醒来」的温柔基调冲突。
2. **省掉一整套 UI**：不需要致死预告、不需要代价预览、不需要「这一下会不会死」的红色警告——STS 为此专门加了 `ThatDoesDamage` / `ThatWillKillPlayerIf` 两个字段。
3. **代价的长期性交给上限削减**：短期损失用侵蚀（可自然恢复），长期损失用「生命上限 −5」（不可逆）。两者分工清晰，玩家一眼能懂哪个更疼。

**上限削减同样有底**：最低削到 1 点上限；削减后当前生命跟随钳制。

### 2.4 事件读局面（动态文案）

所有事件都可以引用本局真实数据填文案。可用变量：

| 变量 | 含义 | 示例 |
|---|---|---|
| `{Floor}` | 当前层数 | 「你已经走了 6 层」 |
| `{LostHp}` | 本局累计失去生命 | 「丢了 23 点血」 |
| `{HpPercent}` | 当前生命百分比 | 用于「你看起来很累」分支 |
| `{PotionCount}` | 药水槽占用数 | 「还攥着 2 瓶没舍得喝的药」 |
| `{DeckSize}` | 牌组张数 | 「九张牌，够不够走到顶」 |
| `{TopType}` | 牌组里最多的卡牌类型 | 「你偏爱挥拳」 |
| `{ShardCount}` | 已收集碎片数 | 「你身上有别人的东西」 |
| `{ShardSource1..3}` | 三枚碎片的来源事件名 | 「低语空洞、梦隙之桥、无名碑」 |
| `{LastUpgraded}` | 最近一次升级的卡名 | 「它念出『痛击』」 |

**原则**：动态变量只用来**指认真实发生过的事**，不用来卖弄。一则事件的正文最多 3 个变量，多了就像仪表盘。

## 3. 事件总表与池划分

### 3.1 池

沿用 `SO_MonsterPool` 的做法：**分档是池自己的知识，调用方只说「第几层、浓度多少」**。

| 池 | 层 | 成员 | 准入 |
|---|---|---|---|
| 浅梦池 | 1~3 | E01 E02 E03 E04 | 无；浓度 ≤2 时权重 ×1.5（新手优先遇温和事件） |
| 执念池 | 4~7 | E05 E06 E07 E08 E09 | 无 |
| 沉眠池 | 8+ | E10 E11 E12 | 浓度 ≥4 |
| 隐藏 | 任意 | E13 | 碎片 ≥3 且未完成过，**优先于当层抽取** |

- **同局不重复**：`RunState.VisitedEvents` 记录已访问 ID，抽到就排除，全池耗尽才允许重复（与 STS 的 `EnsureNextEventIsValid` 同义）。
- **事件密度**：地图未落地，暂定「每 3 层 1 个事件」，一局约 4 次事件 —— 这也是浓度门控要定在 3/4/5/6 而不是更高值的原因（一局摸不到 8）。

## 4. 逐则设计

> 每则统一字段：**背景 / 层级 / 结构 / 页 1 文案 / 选项 / 后续页 / 原创点 / 边界 / 依赖**。
> 「背景图」即它的 STS 原型 ID；下面写的是 DreamKeep 版**重做**，不是原事件的翻译。
> 文案为设计稿，落码时可微调，但不得加长到超过 90 字/页。

### 4.0 与原型的关键差异（只列改动大的）

| 本作 | STS 原型 | 原型做什么 | 本作怎么改 | 为什么 |
|---|---|---|---|---|
| E01 低语空洞 | Whispering Hollow | 50 金换 2 药水 / 变牌 +9 伤 | 听它说话：碎片 + 浓度，文案复述本局真实数据 | 用「它知道你的过去」替代纯数值交换，第一次建立「事件认识我」 |
| E03 两扇门 | This or That | 固定二选一（受伤换金币 / 诅咒换遗物） | 三选一，第三扇「门缝」由浓度解锁 | 让浓度第一次变成可见的**资格**，而不是隐藏数值 |
| E05 梦隙之桥 | Slippery Bridge | 无限循环撑桥，随机丢牌，次数越多越痛 | 固定 4 段、代价递增、放手按段数给钱 | 去掉无限循环的疲劳感，改成可读的 4 步「你愿意走多远」 |

| E12 镜中守梦人 | Reflections | 降级 2 张换升级 4 张 / 克隆整个牌组 + 诅咒 | 复制**最强的一张** / 移除 1 张 + 金币 / 遗物 ×2 | 克隆整组会直接打穿平衡，复制单张已经够强 |

### E01 低语空洞（Whispering Hollow）

- **背景**：`whispering_hollow.png` ｜ **层级**：浅 ｜ **结构**：二页
- **页 1**：
  > 走廊的墙在说话。它先叫了一声你的名字，然后说出你昨天没说完的那半句话。
- **选项**：

| 选项 | 副标题 | 效果 | 条件 |
|---|---|---|---|
| 听清它在说什么 | — | 碎片 +1，浓度 +1 → 页 2 | — |
| 把耳朵捂上，快走 | 金币 +40 | 金币 +40，结束 | — |
| 应它一声 | 生命 −8 ｜ 升级 1 张 | 侵蚀 8，升级 1 张（选），结束 | 浓度 ≥3 |

- **页 2**（听）：
  > 它说：你已经走了 {Floor} 层，丢了 {LostHp} 点血，手里还攥着 {PotionCount} 瓶没舍得喝的药。它问你——你还记得自己为什么上来吗？

| 选项 | 副标题 | 效果 |
|---|---|---|
| 回答它 | 碎片 +1 ｜ 浓度 +1 | 碎片 +1，浓度 +1，结束 |
| 不回答 | 生命 +8 ｜ 浓度 −1 | 回血 8，浓度 −1，结束 |

- **原创点**：第一个「事件知道我是谁」的时刻。页 2 文案全部由 `RunState` 真实数据填充，玩家会停下来读。碎片设计成「一次贪到 2 枚」而不是 1 枚，是为了让凑满 3 枚只需要 2 次相遇，而不是 3 次。
- **边界**：碎片已满 3 时，页 2「回答它」改为「金币 +60」；浓度为 0 时「不回答」不降浓度（不显示 −1）。
- **依赖**：A（浓度/碎片字段 + 动态文案）

### E02 醒泉（Wellspring）

- **背景**：`wellspring.png` ｜ **层级**：浅 ｜ **结构**：单选
- **页 1**：
  > 一汪泉，水面上浮着塔顶的光。你伸手，光就散；你不动，光又聚回来。泉边放着三样东西：一个空瓶、一把钝刀、一块干净的布。
- **选项**：

| 选项 | 副标题 | 效果 |
|---|---|---|
| 喝下去 | 生命 +24 ｜ 浓度 −1 | 回血 24（30% 上限），浓度 −1 |
| 洗净身上的梦 | 移除 1 张 ｜ 上限 −5 | 移除 1 张（选），上限 −5 |
| 装满一瓶 | 获得 1 瓶药水 | 随机药水；槽位已满则改为金币 +40 |

- **原创点**：一则事件同时给出「三种货币」的兑换率（生命 / 牌组 / 药水），让玩家在第一次遇到事件时就建立价值感。三种代价的写法（免费+浓度、上限、占槽）互不重复。
- **边界**：满血时「喝下去」仍可选（提示「水会溢出来」但照给浓度 −1 的净化）；牌组只剩 1 张时「洗净」锁定（不能删空）。

### E03 两扇门（This or That）

- **背景**：`this_or_that.png` ｜ **层级**：浅 ｜ **结构**：单选

  > 两条岔路。左边的门底下漏进来一线晨光，右边的门缝里往外渗水，水是温的。你贴上去听，右边的门后面有心跳。
- **选项**：

| 选项 | 副标题 | 效果 | 条件 |
|---|---|---|---|
| 推左门 | 升级 2 张 ｜ 浓度 −1 | 升级 2 张（选），浓度 −1 | — |
| 推右门 | 金币 +55 ｜ 浓度 +1 | 金币 +55，浓度 +1 | — |

- **原创点**：第三个选项不是「更好的奖励」，而是「第三种走法」——两扇门之间的夹缝，只有已经足够清醒（或足够深）的人才看得见。它把浓度第一次变成**可见的资格**。

### E04 碎片堆（Trash Heap）

| 选项 | 副标题 | 效果 |
|---|---|---|

### E05 梦隙之桥（Slippery Bridge）

### E11 晨门·夜门（Doors of Light and Dark）

- **页 1**：
  > 两扇门并排立着，中间没有墙。左边那扇底下是晨光，右边那扇底下什么都没有——连影子都没有。

|---|---|---|

- **触发**：碎片 ≥3 且本局未完成过；优先级高于当层抽取（占掉那次事件机会）。
- **页 1**：
  > 走廊尽头有人在唱。你走近，才听清那不是歌——是三段你捡到过的记忆，被一句一句唱回来：{ShardSource1}、{ShardSource2}、{ShardSource3}。唱完，它们停在你面前，等你决定。
- **选项**：

| 选项 | 副标题 | 效果 |
|---|---|---|

| 忘掉 | 遗物 ×1 ｜ 药水 ×3 ｜ 浓度 +2 | 获得 1 件遗物与 3 瓶随机药水，浓度 +2，碎片清零 |

## 5. 数值基准

### 5.1 各资源的兑换率（按 80 生命 / 99 金币 / 9 张牌标定）

| 资源 | 单次事件允许范围 | 依据 |
|---|---|---|
| 侵蚀（生命损失） | 3 ~ 15 | 6 伤卡 ≈ 一次普攻；15 ≈ 两次普攻，不致死所以可以偏重 |
| 生命上限削减 | 5 ~ 10 | 5 ≈ 6% 上限；10 是深梦级，配合大奖励 |
| 生命上限增加 | +2 / 次，一局 ≤ +8 | 超过 8 就变成「堆上限」玩法，压过卡组成长 |
| 回血 | 8 ~ 24（满血事件除外） | 24 ≈ 30% 上限 |
| 金币收入 | 30 ~ 60 | 起始 99，E06 一次 20~40，收支要能转起来 |
| 金币支出 | 20 ~ 40 / 次 | 目前唯一出口是 E06 |
| 遗物 | 1（深梦 2，E09 最多 3） | 现有 9 件全部已持有，必须先做池与去重 |
| 药水 | 1（E13 给 3） | 槽位 3，满槽时必须给替代奖励 |
| 卡牌加入 | 1（三选一） | 9 张牌组里加 1 张 = +11%，份量已经够 |
| 卡牌移除 | 1（深梦 2） | 删 1 张 = −11%，是最强的构筑手段之一 |
| 卡牌升级 | 1 ~ 2 | 9 张牌组里升级 2 张已经很奢侈 |
| 记忆碎片 | 1 ~ 2（一局总供给 3~4） | 保证一局能凑满一次 |
| 浓度 | ±1 ~ ±3 | 一局约 4 次事件，门控定在 3/4/5/6 |

### 5.2 跑图落地后的重标口径

当前是演示配置（9 张牌 / 全遗物 / 2 药水）。真实跑图落地后按以下比例换算：

- **牌组规模** → 目标 18~25 张：移除/升级的「1 张」保持不变，但「移除 2 张」从深层事件解禁。
- **遗物** → 目标 8~12 件持有 / 池 30+：遗物事件的供给改为「按稀有度从池抽」，`E09` 的价格改为「上限 5/10/15 + 金币 50/100/150」双轨。
- **金币** → 商店落地后，事件金币收入降到 20~40，避免和商店抢节奏。

## 6. 抽取规则

```text
进事件段时：
1. 若 碎片 ≥ 3 且 E13 未完成 → 必抽 E13（占掉本次事件）
2. 否则按当前层取池：1~3 浅梦 / 4~7 执念 / 8+ 沉眠
3. 沉眠池要求 浓度 ≥ 4，不足则回退执念池
4. 从池中排除 VisitedEvents，按权重抽 1（浓度 ≤2 时浅梦池权重 ×1.5）
5. 记录 VisitedEvents，进入事件
```

- 随机源统一走 `RunState.Rng`（同种子可复现），不新建随机流。
- 权重写在 `SO_EventPool` 上（每则事件一个 `weight` 字段），不散落在代码里。
- 「重复访问」只有两种：E09（同一次事件内重复兑换）与 E13 的「留着」（跨次数保留资格）。其余一律一局一次。

## 7. 落位与数据结构

### 7.1 程序集与目录（沿用现有依赖方向）

| 层 | 位置 | 内容 |
|---|---|---|
| 配置 | `ConfigData/Event/` | `SO_Event`（**单类，非抽象**）、`SO_EventPool`、`EventPage`、`EventOptionData`、`EventEffectData`+`ED_*`、`EventCondition`+`EC_*` |
| 运行时 | `RuntimeData/Event/` | `EventModel`（当前页 / 计数器 / 条件求值）、`EventOption` |
| 域 | `GameEvent/` | `EventService`（抽事件、开始、选选项、结束）、`EventEffectRunner`（按列表顺序执行效果） |
| 整局状态 | `GameRun/Run/RunState.cs` | 增 `DreamDensity`、`MemoryShards`、`VisitedEvents`、`ShardSources`、`TotalLostHp`（供 `{LostHp}` 文案） |
| 表现 | `Presentation/Event/` + `Presentation/_Bootstrap/Event/` | `EventLifetimeScope`、`EventEntry`、`UI_EventPanel`、`UI_EventOption`、`UI_EventCardPicker` |
| 场景 | `Assets/_Scenes/Scene_Event.unity` | additive 段，由 `SegmentSceneLoader` 加载（该类注释已预留「事件段」） |

**依赖方向**：`Presentation → GameEvent → {RuntimeData, ConfigData, GameRun}`。事件不认识战斗，只认识 `RunState`。

### 7.2 配置形状（示意，不是代码）

```text
SO_Event
├─ _eventId        string          // 去重与存档键
├─ _title          string
├─ _background     Sprite          // 对应 _Art/Sprites/Event/xxx.png
├─ _weight         float
└─ _pages          List<EventPage> // 入口 = 第一个 visibleIf 通过的页

EventPage
├─ _id             string          // 跳转目标
├─ _text           string          // 支持 {Floor} / {段数} 等占位符
├─ _visibleIf      EventCondition  // 页级分流（E11 的三档浓度）
└─ _options        List<EventOptionData>

EventOptionData
├─ _title / _subtitle / _tip       string   // 副标题写代价，tip 写补充说明
├─ _visibleIf      EventCondition           // 不满足即不显示
├─ _enabledIf      EventCondition           // 不满足则锁定（可见灰）
├─ _lockedHint     string                   // 锁定时显示的原因
└─ _effects        List<EventEffectData>    // 顺序执行
```

**为什么不是「一事件一子类」**：STS2 的 68 个事件 = 68 个 C# 类，因为每个事件都在代码里写自己的选项生成逻辑。本工程把差异全部收敛成四样东西——**页、条件、效果、计数器**（E05 的段数、E06 的级数、E07 的层数、E09 的兑换次数、E11 的浓度分流），所以 13 个事件 = 13 个资产，新增事件**零编译、零代码**。只有确实表达不了的情况（例如将来要写「按牌组构成生成 N 个选项」）才允许加一个 `ED_*` / `EC_*`，不准开事件子类。

**效果族**（每个一个类，与 `AD_*` / `UD_*` 同风格）：

`ED_GainGold` / `ED_LoseGold` / `ED_LoseHp`（侵蚀，不致死）/ `ED_Heal` / `ED_HealPercent` / `ED_GainMaxHp` / `ED_LoseMaxHp` / `ED_AddCard` / `ED_AddCurse` / `ED_RemoveCard`（进选牌页）/ `ED_UpgradeCard`（可带类型过滤）/ `ED_GainRelic` / `ED_GainPotion` / `ED_GainShard` / `ED_AdjustDensity` / `ED_AddCounter`（段数/级数/层数/兑换次数）/ `ED_SetPage` / `ED_EndEvent`

**条件族**：`EC_DensityAtLeast` / `EC_DensityAtMost` / `EC_HpBelowPercent` / `EC_GoldAtLeast` / `EC_HasShard` / `EC_PotionSlotNotEmpty` / `EC_DeckHasType` / `EC_DeckHasUpgradableType` / `EC_CounterAtLeast`

### 7.3 需要补的局外 API（按优先级）

| API | 现状 | 改法 | 被谁需要 |
|---|---|---|---|
| 生命上限增减 | `Creature.MaxHp` 只读 | 改为 `{ get; private set; }` + `GainMaxHp(int)` / `LoseMaxHp(int)`，内部钳制 | E02 E06 E07 E09 E11 E12 |
| 回血 | 只有 `CurrentHp` setter | `Creature.Heal(int)`（钳到上限） | 全部 |
| 侵蚀 | 无 | `Creature.LoseHp(int)`（最低 1，不触发死亡） | E01 E05 E10 |
| 药水发放 | 只有 `TryTakePotion` | `Player.TryAddPotion(SO_Potion, out int slot)` | E02 E06 E13 |
| 遗物发放 | `Relics` 只读 | `Player.AddRelic(SO_Relic)` + 遗物池去重 | E05 E09~E13 |
| 卡牌移除 | `CardPile.Remove` 已有 | 直接可用 | E02 E03 E11 E12 |
| 卡牌加入 | `CardModelBaker.Bake().ToMutable()` | 直接可用 | E04 E06 E10 E11 E12 |

### 7.4 表现层可复用的现成件

| 需求 | 复用 |
|---|---|
| 事件里的卡牌展示与选择 | `UI_CardFace`（四张脸按类型切换）+ `Card_Face` 预制体 |

### 7.5 UI 结构（Scene_Event）


## 8. 实施分期

| 期 | 目标 | 内容 | 需补的 API |
|---|---|---|---|
| **P0** | 管道跑通 + 3 则事件 | 事件段场景、`SO_Event` 数据形状、`EventModel` 状态机、效果/条件族的 A 类子集、UI_EventPanel、选牌浮层；事件 E01 E03 E04 | 金币、回血、侵蚀、移除卡、升级卡（全部现有或 1 行） |
| **P1** | 铺到 7 则 | 补上限增减、药水发放；E02 E06 E07 E08 | `Creature.GainMaxHp/LoseMaxHp`、`Player.TryAddPotion` |
| **P2** | 铺满 13 则 | 遗物池与去重、碎片来源记录、浓度门控与 E11 分流、E13 隐藏触发；E05 E09 E10 E11 E12 E13 | `Player.AddRelic`、遗物池、`RunState.ShardSources` |
| **P3** | 浓度入战斗（可选） | 下一场战斗的开局修正（浓度 ≥6：敌人 +1 力量 / 首个意图可见 / 最前敌人后退一格） | `BattleSetup` 读整局状态 |

**为什么 P0 只做 3 则**：管道（数据形状 + 状态机 + 段场景 + 选牌）是真正的工作量，事件本身只是数据和文案。管道跑通后，一则新事件的成本 ≈ 一个 `SO_Event` 资产 + 一段文案 + 一小时调数值，**不需要改代码**。

**刻意不做**：附魔、变换、事件内战斗、联机投票、自定义小游戏、元进度积分。它们在 `_事件系统总览.md` 里都是 T3/T4 级投入，与本项目「先做能玩的闭环」冲突。

## 9. 验收清单

**管道**
- [ ] 进事件段 → 背景、标题、正文、3 个选项正确显示；选项副标题含代价。
- [ ] 条件不满足的选项锁定且显示原因；不满足可见条件的选项完全不显示。
- [ ] 选完 → 效果按列表顺序执行 → 换页或结束；结束后段卸载、层数 +1。
- [ ] 同局不重复；同种子同结果。

**三条机制**
- [ ] 浓度 0~8 钳制；+/- 后立即影响下一次事件的可见选项与抽取池。
- [ ] 侵蚀最低留 1 生命；上限削减最低到 1，且当前生命跟随钳制。
- [ ] 碎片 3 枚时下一次事件必为 E13；E13 选「留着」后下次仍可出现。

**边界**
- [ ] 满血时回血选项、空药水槽时以药水为代价的选项、金币不足时花金币的选项，全部走「锁定」而不是静默无效。
- [ ] 牌组只剩 1 张时移除类选项锁定。
- [ ] 无对应类型可升级卡时 E08 的对应玩偶锁定。

**表现**
- [ ] 背景图不拉伸（Cover）、文字在 2048×962 与 16:9 下都不溢出。
- [ ] 选牌浮层与手牌风格一致（复用 `UI_CardFace`）。
- [ ] 事件结束回到跑图后，顶栏金币/生命/层数立即刷新。
