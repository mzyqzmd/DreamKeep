# 《杀戮尖塔 2》(Slay the Spire 2) 药水系统总览

> 基于本地工程 `src/Core/**` 逐文件扫描生成，覆盖 **64 个药水模型**（`src/Core/Models/Potions/*.cs`）与全部 9 个药水池定义。
> 中文名/描述取自 `localization/zhs/potions.json`；数值、目标类型、钩子名均来自源码，未做估算。
> 统计口径："种数"指**模型类**数量，含 1 个占位废弃品（DeprecatedPotion）。
> 分析范围按项目约定**排除联机/同步层**（网络 action、同步器等），只保留单人版逻辑。

---

## 0. 结论摘要

1. **64 种药水分四个正交维度**：发放池 `PotionPoolModel`（9 个）、稀有度 `PotionRarity`（6 值）、使用时机 `PotionUsage`（4 值）、目标类型 `TargetType`。掉落时的候选集 = **角色池 ∪ 共享池**，与卡牌池同构。
2. **稀有度分布**：Common 20 / Uncommon 19 / Rare 21 / Event 2 / Token 1 / None（占位）1。抽取时**先滚稀有度再选药水**：Rare 10% / Uncommon 25% / Common 65%——与遗物的 50/33/17 不同（`PotionFactory.cs:39-53`）。
3. **药水 = 挂钩子的参数化模型，不是特例系统**：全部 64 种都是扁平的 `PotionModel` 子类（零继承复用），效果靠 `OnUse` 覆写 + `CanonicalVars` 动态数值 + `PowerCmd` 等通用命令实现，与遗物/卡牌共用同一套 `AbstractModel` 两态与钩子分发。
4. **最独特的三个机制**：① 瓶中精灵用 `ShouldDie` + `AfterPreventingDeath` 双钩子接入死亡结算链实现免死（§4.1）；② 肌肉/速度/镣铐药水用 `TemporaryStrengthPower` 家族实现"借力量、回合末归还"（§4.2）；③ 污浊药水用动态 `TargetType` + `PassesCustomUsabilityCheck` 实现"战斗中扔敌人、战斗外扔商人"的双形态（§4.3）。
5. **解锁门控走 Timeline Epoch**：共享池 6 种被 Potion1/2Epoch 门控；5 个角色池整体门控在各自角色 4Epoch reveal 上（§2.5）。

## 1. 系统分层：药水在代码里的位置

| 层 | 类型 / 文件 | 职责 |
|---|---|---|
| 模型层 | `PotionModel : AbstractModel`（`Models/PotionModel.cs`，307 行） | 单种药水的数据 + `OnUse` 覆写；canonical（配置）/ mutable（运行时）两态 |
| 分类层 | `PotionRarity`、`PotionUsage`（`Entities/Potions/`）+ `TargetType`（`Entities/Creatures/`） | 稀有度、使用时机、目标类型三个枚举 |
| 池层 | `PotionPoolModel` + 9 个子类（`Models/PotionPools/`） | 按发放渠道划分；`ShouldReceiveCombatHooks => false`，池本身不参与战斗 |
| 工厂层 | `PotionFactory`（`Factories/PotionFactory.cs`） | 滚稀有度 → 从「角色池+共享池」选药水 → `ToMutable()` |
| 命令层 | `PotionCmd`（`Commands/PotionCmd.cs`）+ `UsePotionAction` / `DiscardPotionGameAction`（`GameActions/`） | 获取（TryToProcure）、使用、丢弃的唯一合法入口 |
| 实体层 | `Player._potionSlots`（`Entities/Players/Player.cs`）+ `AddPotionInternal` / `RemoveUsedPotionInternal` / `DiscardPotionInternal` | 槽位归属；`Owner` 设置后不可转移（换主抛异常） |
| 表现层 | `NPotion`、`NPotionHolder`、`NPotionPopup`、`NPotionShortcutButton`（`Nodes/Potions/`）+ `NPotionLab`（药水实验室图鉴） | 图标（potion_atlas）、tooltip、投掷动画 |

**关键契约**：药水是战斗钩子监听者（`PotionModel.ShouldReceiveCombatHooks => true`），在 `IterateHookListeners()` 中的位置是「生物 → Powers → 遗物 → **药水** → Orbs → 牌组卡牌 → Modifiers」。战斗外同样被遍历，因此药水也能响应非战斗钩子（如瓶中精灵的免死钩子在任意房间生效）。

- **共享池 6 种**被 `Potion1Epoch`（甲虫汁、马萨雷斯的赠礼、预知之滴）和 `Potion2Epoch`（消亡粉末、瓶中船、癫狂之触）门控：epoch 未 reveal 时 `GetUnlockedPotions` 把它们从池里移除。

## 4. 独特机制实现

### 4.1 瓶中精灵：双钩子接入死亡结算链

不自己监听死亡，而是覆写 `AbstractModel` 的两个钩子：

```csharp
public override bool ShouldDie(Creature creature)
    => creature != Owner.Creature;              // 主人将死 → 返回 false（不许死）

public override async Task AfterPreventingDeath(Creature creature)
    => await OnUseWrapper(new ThrowingPlayerChoiceContext(), creature);  // 直接走完整使用流程回 30% 血
```

死亡结算在 `CreatureCmd.KillWithoutCheckingWinCondition`（`Commands/CreatureCmd.cs:359-421`）：

1. `Hook.ShouldDie(...)` 遍历所有监听者，瓶中精灵对主人返回 false → 进入 **else 分支**（免死分支）；
2. 先 `Hook.AfterDeath(wasRemovalPrevented: true)`，再 `Hook.AfterPreventingDeath(preventer, creature)` —— 药水在这里被回调，`OnUseWrapper` 里先 `RemoveBeforeUse()` 把自己从槽位移除（消耗），再治疗；
3. 若治疗后仍处于死亡状态，递归重判，`recursion >= 10` 抛 `InvalidOperationException` 防"永远打不死"死循环。

注意 `Usage = Automatic` 且 `CanBeGeneratedInCombat = false`——不在战斗中生成，只能事件/商店等渠道获得，正是 StS 的规则。

### 4.2 肌肉/速度/镣铐药水：TemporaryStrengthPower 家族

```csharp
public class FlexPotionPower : TemporaryStrengthPower { OriginModel => ModelDb.Potion<FlexPotion>(); }
public class ShacklingPotionPower : TemporaryStrengthPower { OriginModel => ...; protected override bool IsPositive => false; }
public class SpeedPotionPower : TemporaryDexterityPower { ... }
```

`TemporaryStrengthPower`（`Models/Powers/TemporaryStrengthPower.cs`）本身是个"影子 Power"：

- `BeforeApplied` / `AfterPowerAmountChanged`：挂载和层数变化时**静默**（`silent: true`）给目标应用/追加真实的 `StrengthPower`；
- `AfterTurnEnd`：`PowerCmd.Remove(this)` 移除自身，同时 `PowerCmd.Apply<StrengthPower>(-Amount)` 把借来的力量**扣回去**；
- `IsPositive` 控制正负：镣铐药水覆写为 false → `Sign = -1`，给敌人挂的是负力量，且 `Type` 自动变 `PowerType.Debuff`；
- `Title` / `ExtraHoverTips` 通过 `OriginModel` 回源到药水名与图标——一套 Power 代码被药水/卡牌/遗物三者共用（`HoverTipFactory.FromPotion`）。

### 4.3 污浊药水：动态 TargetType + 自定义可用性 + 商人交互

```csharp
public override TargetType TargetType =>
    CombatManager.Instance.IsInProgress ? TargetType.AllEnemies : TargetType.TargetedNoCreature;

public override bool PassesCustomUsabilityCheck =>
    CombatManager.Instance.IsInProgress
    || Owner.RunState.CurrentRoom is MerchantRoom
    || (CurrentRoom is EventRoom r && r.CanonicalEvent is FakeMerchant);
```

- `Usage = AnyTime` + 战斗中 `AllEnemies`：`OnUse` 对 `CombatState.Creatures`（**全体生物**，含玩家自己）造成 12 伤——自伤设计；
- 战斗外在商人房：播 slime impact VFX 到商人按钮，调 `MerchantRoom.FoulPotionThrown(this)` 打折，+100 金；
- 在假商人事件房：遍历所有玩家逐个触发 `FakeMerchant.FoulPotionThrown`；
- 这是唯一重写 `TargetType` 为非常量、且重写 `PassesCustomUsabilityCheck` 做房间级准入的药水。

### 4.4 异蛇之油：独立 RNG 流随机化手牌费用

```csharp
await CardPileCmd.Draw(choiceContext, 7, target.Player);
foreach (var c in Hand.Cards.Where(c => !c.EnergyCost.CostsX))
    if (c.EnergyCost.GetWithModifiers(CostModifiers.None) >= 0)
        c.EnergyCost.SetThisTurnOrUntilPlayed(NextEnergyCost());  // 0-3

private int NextEnergyCost() =>
    TestEnergyCostOverride >= 0 ? TestEnergyCostOverride
                                : Owner.RunState.Rng.CombatEnergyCosts.NextInt(4);
```

要点：① 跳过 X 费牌；② 随机数走**专用 RNG 流** `CombatEnergyCosts`（与其它随机事件解耦，保证种子/回放一致）；③ `TestEnergyCostOverride` 仅供测试模式注入固定值（`TestMode.AssertOn()` 守卫）；④ 每张牌播 `PlayRandomizeCostAnim`。

## 5. 运行时架构

### 5.1 两态模型（与卡牌/遗物同一套）

canonical（ModelDb 注册的配置态）→ `ToMutable()`（`MutableClone` + 置 `IsMutable` + 记 `_canonicalInstance`）→ 运行时实例持 `_owner`。`Owner` 只允许设置一次，换主抛 `InvalidOperationException`。序列化只存 `ModelId + SlotIndex`（`SerializablePotion`），读档时 `SaveUtil.PotionOrDeprecated(id).ToMutable()` 重建。

### 5.2 使用流程

```
玩家点击 → PotionModel.EnqueueManualUse(target)
  → BeforeUse 事件 → new UsePotionAction(...) → RequestEnqueue 入队
  → OnUseWrapper(choiceContext, target):
      1. RemoveBeforeUse()                先离槽（消耗）
      2. Hook.BeforePotionUsed(...)
      3. 播 NItemThrowVfx 投掷动画（await 0.5s；TestMode 跳过）
      4. await OnUse(...)                 ← 子类效果
      5. InvokeExecutionFinished()
      6. Hook.AfterPotionUsed(...) + CombatHistory.PotionUsed + 地图历史记录
      7. CheckForEmptyHand（打完牌空手检测）
```

`AssertValidForTargetedPotion(target)` 是所有指向型药水的统一前置校验。取消使用走 `AfterUsageCanceled()` 清 `IsQueued`。

### 5.3 获取 / 丢弃

- 获取：`PotionCmd.TryToProcure` → `Hook.ShouldProcurePotion`（可被遗物等拦截）→ `Player.AddPotionInternal`（满槽/槽位冲突返回失败原因）→ 成功后 `Hook.AfterPotionProcured` + 音效 + 顶栏动画 + `MarkPotionAsSeen`。
- 丢弃：`DiscardPotionGameAction`（按槽位索引）→ `PotionCmd.Discard` → `Hook.AfterPotionDiscarded` + 历史记录。

### 5.4 槽位

`Player.PotionSlots` 是 `List<PotionModel?>`，长度 = 当前最大栏位；药水腰带遗物 `PotionBelt` 拾取时 +2，高阶 Ascension 开局 -1。`HasOpenPotionSlots` 供奖励屏/混沌药水判断。

### 5.5 数值与描述

- 数值全部走 `CanonicalVars`（`DamageVar` / `BlockVar` / `PowerVar<T>` / `EnergyVar` / `CardsVar` / `RepeatVar` / `MaxHpVar` / `SummonVar` / `StarsVar` / `ForgeVar` / 自定义 `DynamicVar("Demise", 9)`），描述模板用 `{Damage}` 占位，`DynamicDescription` 统一替换。
- 图标路径约定：`atlases/potion_atlas.sprites/<ID 小写>.tres`，描边 optional（`potion_outline_atlas`）。
- 悬停由 `HoverTip` + `ExtraHoverTips` 组成（关联 Power / 关键字 / 卡牌的图标链）。
