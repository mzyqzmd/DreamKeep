# 《杀戮尖塔 2》(Slay the Spire 2) 商店系统总览

> 基于本地工程 `src/Core/**` 逐文件扫描生成，覆盖商人房间（`MerchantRoom`）、库存实体（`Entities/Merchant/`）、槽位 UI（`Nodes/Screens/Shops/`）及全部商店相关钩子实现。
> 中文名取自 `localization/zhs/merchant_room.json`；数值、概率、钩子名均来自源码，未做估算。
> 分析范围按项目约定**排除联机/同步层**（网络消息、同步器等，清单见附录），只保留单人版逻辑。

---

## 0. 结论摘要

1. **商店 = 房间 + 库存 + 槽位三层**：`MerchantRoom`（模型）/ `NMerchantRoom`（场景）只管房间生命周期；`MerchantInventory` + `MerchantEntry` 是纯数据货架；`NMerchantSlot` 四个子类只管表现。UI 节点只调 `MerchantEntry` 公开成员，购买是 async Task，成交靠事件广播驱动刷新。
2. **货架固定配比**：角色卡 5（攻2/技2/能1，随机 1 张半价）+ 无色卡 2（罕见+稀有，价×1.15）+ 遗物 3（2 个滚稀有度 + 1 个固定 Shop 级）+ 药水 3 + 删牌服务 1 次。
3. **定价三段式**：基础价表 → 随机浮动（卡/药 ±5%，遗物 ±15%，走 `PlayerRng.Shops` 专用流）→ `Hook.ModifyMerchantPrice` 修正管道（TheCourier ×0.8 / MembershipCard ×0.5，乘性叠加）。**扣款用的是修正后价格**。
4. **补货是 Hook 不是硬编码**：`ShouldRefillMerchantEntry`（TheCourier 持有者返回 true）决定买后补货还是清空格子；`ModifyMerchantCardCreationResults`（Egg 家族/菲涅尔透镜）在生成时就直接改造商店卡。
5. **删牌服务价格递增**：75 金起步，每次使用 +25，计数存 `ExtraPlayerFields.CardShopRemovalsUsed`（随存档持久化）。
6. **两个"非标准商店"**：FoulPotion 可在商店里对商人使用（+100 金）；假商人事件是一整个可战斗的"商店房"（6 件遗物库存，扔药水开战，战后库存全数掉落）。

## 1. 系统分层

| 层 | 类型 / 文件 | 职责 |
|---|---|---|
| 房间层 | `MerchantRoom : AbstractRoom`（`Rooms/MerchantRoom.cs`，105 行） | `RoomType.Shop`；进入时生成库存、预载资产、建场景；退出时把未购库存写进地图历史 |
| 房间 UI | `NMerchantRoom : Control`（`Nodes/Rooms/NMerchantRoom.cs`） | 商人角色（`NMerchantCharacter`）+ 商人按钮 + 购物袋开合 + FTUE 弹窗 |
| 库存层 | `MerchantInventory`（`Entities/Merchant/MerchantInventory.cs`） | 四张货单（角色卡/无色卡/遗物/药水）+ 删牌条目；统一订阅成交广播 |
| 条目层 | `MerchantEntry`（抽象）+ 4 子类（`Entities/Merchant/Merchant{Card,Relic,Potion,CardRemoval}Entry.cs`） | 价格计算、购买逻辑、补货/清空；事件 `PurchaseCompleted` / `PurchaseFailed` / `EntryUpdated` |
| 槽位 UI | `NMerchantSlot`（抽象，`Nodes/Screens/Shops/NMerchantSlot.cs`）+ `NMerchantCard` / `NMerchantRelic` / `NMerchantPotion` / `NMerchantCardRemoval` | 每格货摊：价格标签、hover 缩放、购买失败抖动、商人手指向 |
| 购物袋 UI | `NMerchantInventory : Control`（`Nodes/Screens/Shops/NMerchantInventory.cs`） | 容器管理、开关动画、手柄导航织网（横/纵 FocusNeighbor）、对话气泡 |

**关键契约**：UI 不直接改库存状态，一律 `entry.OnTryPurchaseWrapper(inventory)`；`MerchantEntry.Cost` 是**每次读取都重算**的属性（getter 内过 Hook），而非缓存字段。

## 2. 货架构成与生成

### 2.1 固定配比（`MerchantInventory.CreateForNormalMerchant`）

| 货单 | 数量 | 生成规则 | 代码 |
|---|---|---|---|
| 角色卡 | 5 | 类型固定配比 Attack×2 / Skill×2 / Power×1；按类型从角色卡池抽取；**随机 1 张 `SetOnSale()` 半价** | `PopulateCharacterCardEntries` |
| 无色卡 | 2 | Uncommon 1 + Rare 1，从 `ColorlessCardPool` 抽取 | `PopulateColorlessCardEntries` |
| 遗物 | 3 | 2 个 `RelicFactory.RollRarity`（普通 50% / 罕见 33% / 稀有 17%）+ 1 个固定 `RelicRarity.Shop` | `PopulateRelicEntries` |
| 药水 | 3 | `PotionFactory.CreateRandomPotionsOutOfCombat(player, 3, PlayerRng.Shops)`：先滚稀有度（稀有 10% / 罕见 25% / 普通 65%）再选具体药水，同批去重 | `PopulatePotionEntries` |
| 删牌服务 | 1 次 | 价格 75 起，见 §3.4 | `new MerchantCardRemovalEntry(player)` |

卡牌生成链（`CardFactory.CreateForMerchant`）：`Hook.ModifyMerchantCardPool` 改池 → 剔 Basic → 按人数过滤 → 滚稀有度（`CardRarityOddsType.Shop`）→ 若该稀有度+类型组合为空则向更高稀有度降级查找 → `RunState.CreateCard` → `RollForUpgrade(..., -999999999m)`（实际禁升级，升级交给 Egg 类遗物的 Hook）。

### 2.2 去重与黑名单

- **卡牌**：`Populate` 时 `_cardPool.Except(second)`，`second` = 库存所有已生成卡的 canonical 实例（同屏不出现两张同名卡）；
- **遗物**：`_baseBlacklist = { TheCourier, OldCoin }`（折扣/发财类遗物不入店）；补货时再把当前货架上遗物加入黑名单；
- **药水**：工厂层同批去重；补货时理论上传库存黑名单（注意 `MerchantPotionEntry.RestockAfterPurchase` 实际传的是空数组，补货不去重已上架药水，属小瑕疵）。

### 2.3 商店在地图上的产出

- 每张地图固定 3 个商店点：`MapPointTypeCounts.NumOfShops = 3`（`Map/MapPointTypeCounts.cs`）；
- `MapPointType.Shop` → `RollRoomTypeFor` **直接返回** `RoomType.Shop`（显式映射，不像 Unknown 点要 roll）；
- `RunManager.CreateRoom` → `new MerchantRoom()`；
- `MerchantRoom` **不支持 Resume**（房间栈重建时 `isRestoringRoomStackBase` 抛 `InvalidOperationException`）。

## 3. 定价模型

### 3.1 基础价表

| 条目 | 基础价 | 出处 |
|---|---|---|
| 卡牌 普通/罕见/稀有 | 50 / 75 / 150 | `MerchantCardEntry.GetCost` |
| 无色卡 | 上述 ×1.15 | 同上 |
| 遗物 普通/罕见/稀有/Shop | 200 / 250 / 300 / 225 | `RelicModel.MerchantCost`（cs:275-286） |
| 药水 普通/罕见/稀有 | 50 / 75 / 100 | `MerchantPotionEntry.GetCost` |
| 删牌服务 | 75 + 25×已用次数 | `MerchantCardRemovalEntry.CalcCost` |

### 3.2 随机浮动

- 卡牌 / 药水：±5%（`PlayerRng.Shops.NextFloat(0.95, 1.05)`）；药水在 TestMode 下不浮动；
- 遗物：±15%（`0.85 ~ 1.15`）；
- 半价卡：浮动后再 `/2`（`SetOnSale` 置标志，`CalcCost` 除半）；
- 全部走 `PlayerRng.Shops` **专用 RNG 流**——商店随机与战斗/奖励随机解耦，种子可复现。

### 3.3 Hook 修正管道（每次读价都过）

```csharp
// MerchantEntry.cs:18-26
public int Cost
{
    get
    {
        decimal num = _cost;
        if (_player.RunState.CurrentRoom is MerchantRoom)
            num = Hook.ModifyMerchantPrice(_player.RunState, _player, this, _cost);
        return (int)num;
    }
}
```

`Hook.ModifyMerchantPrice` 遍历 `IterateHookListeners` 全量监听者**乘性叠加**：

| 监听者 | 效果 | 备注 |
|---|---|---|
| `TheCourier`（信使） | ×0.8（-20%） | 无房间限制 |
| `MembershipCard`（会员卡） | ×0.5（-50%） | 额外 `LocalContext.IsMe` 门控（联机产物，单人版等价恒真） |

注意修正只在 `CurrentRoom is MerchantRoom` 时生效（商店外读价不折扣）；且 `OnTryPurchase` 扣款用的正是 `base.Cost`（getter 修正后值）。

### 3.4 删牌服务递增价

```csharp
_cost = 75 + 25 * _player.ExtraFields.CardShopRemovalsUsed;
```

`CardShopRemovalsUsed` 存于 `ExtraPlayerFields`（`SerializableExtraPlayerFields` 随档序列化）——**跨局累加**，用得越多越贵；悬停提示里的 `CalcPriceIncrease()` 显示涨幅 25。

## 4. 购买流程

### 4.1 统一状态机（`MerchantEntry.OnTryPurchaseWrapper`）

```
OnTryPurchaseWrapper(inventory, ignoreCost)
 ├─ EnoughGold 检查（Cost <= Gold）
 │    否 → InvokePurchaseFailed(FailureGold) → return false
 ├─ await OnTryPurchase(inventory, ignoreCost)   ← 子类实现，返回 (success, goldSpent)
 │    否 → 子类已各自 InvokePurchaseFailed（FailureSpace / FailureForbidden）
 └─ success:
      ├─ ShouldRefillMerchantEntry（Hook）
      │    true  → RestockAfterPurchase(inventory)   （补货：重新 Populate/FillSlot）
      │    false → ClearAfterPurchase()              （清空：Model/CreationResult = null）
      ├─ await Hook.AfterItemPurchased(runState, player, this, goldSpent)
      └─ InvokePurchaseCompleted(this)
           → MerchantInventory.UpdateEntries：全库存 OnMerchantInventoryUpdated
             → 每条目重算 CalcCost + EntryUpdated 事件 → UI 刷新（价格/半价标/灰化）
```

UI 侧订阅：`NMerchantInventory` 给每条目挂 `PurchaseCompleted`（迁移焦点 + 商人致谢音效 + 对话）与 `PurchaseFailed`（抖动 + `merchant_dissapointment` 音效 + 台词）。

### 4.2 各条目差异

| 条目 | 购买动作 | 失败原因 | 成功后 |
|---|---|---|---|
| 卡牌 | `CardPileCmd.Add(Deck)` | `FailureSpace`（牌堆满，先入堆再扣款，失败不扣） | 记录 `BoughtColorless`（无色卡才记）；NCardFlyVfx 飞向牌堆 |
| 遗物 | `PlayerCmd.LoseGold` → `RelicCmd.Obtain` | 无（遗物必有位） | 记录 `BoughtRelics`；飞向遗物栏动画 |
| 药水 | `PotionCmd.TryToProcure` | `FailureSpace`（槽满）/ `FailureForbidden`（角色不允许） | 记录 `BoughtPotions`；飞向药水栏动画 |
| 删牌 | `OneOffSynchronizer.DoLocalMerchantCardRemoval` → 牌组选 1 张（可取消、需手动确认）→ `CardPileCmd.Remove` | 取消返回 false | `CardShopRemovalsUsed++`；服务置灰 |

购买失败/成功均有商人语音（`merchant_thank_yous` / `merchant_dissapointment`）。

### 4.3 补货 vs 清空

- **补货**（`RestockAfterPurchase`）：卡牌清半价标重新 `Populate`；遗物滚新稀有度（黑名单 = 当前货架）；药水重新 `FillSlot`；
- **清空**（`ClearAfterPurchase`）：对应 Model/CreationResult 置 null，槽位 `Visible = false` 退出导航织网；
- **删牌**两者皆空实现——它的"消耗"由 `SetUsed()` 单独驱动（UI 走 `OnCardRemovalUsed`）。

## 5. 遗物/修正器的商店 Hook 生态

| Hook | 实现者 | 效果 |
|---|---|---|
| `ModifyMerchantCardPool` | （无内置实现，留扩展点） | 改商店卡候选池 |
| `ModifyMerchantCardRarity` | （无内置实现，留扩展点） | 改滚出的稀有度 |
| `ModifyMerchantCardCreationResults` | `FrozenEgg` / `MoltenEgg` / `ToxicEgg` / `FresnelLens` | **生成时**升级对应类型卡 / 附魔（Nimble×2） |
| `ModifyMerchantPrice` | `TheCourier` / `MembershipCard` | 折扣（§3.3） |
| `ShouldRefillMerchantEntry` | `TheCourier` | 买一件补一件 |
| `AfterItemPurchased` | `MawBank`（嘴咬银行） | 本房间**首次真实消费**后失效 |
| `AfterRoomEntered` | `MawBank` | 每次进商店房且还没买过东西 → +12 金 |
| `ShouldAllowMerchantCardRemoval` | `Hoarder`（囤积者修正） | 返回 false → 删牌服务直接置灰 |

设计要点：**商店本身对这些特性零硬编码**，全部经与战斗数值修正同一套 `IterateHookListeners` 管道挂载。Egg 家族还实现"买卡即升级"：生成时 Hook 改结果，`CardCreationResult.ModifyingRelics` 记录来源，购物袋打开时对修改过源的遗物播 Flash 提示（`NMerchantCard.OnInventoryOpened`）。

## 6. 商店特有交互

### 6.1 删牌服务（Card Removal Service）

- 入口是货架最后一格 `NMerchantCardRemoval`；`Hook.ShouldAllowMerchantCardRemoval` 为 false 时 `SetUsed()` 直接不可用；
- 点击 → 牌组选择器（`CardSelectorPrefs.RemoveSelectionPrompt`，min/max = 1，可取消，需手动确认）→ 确认后扣款移牌；
- 价格递增（§3.4），悬停提示显示"每次使用涨价 25"。

### 6.2 FoulPotion（污浊药水）扔商人

`FoulPotion.OnUse` 按房间三分支：

| 场景 | 行为 |
|---|---|
| 战斗中 | `TargetType.AllEnemies`，对全体生物（含自己）造成 12 伤 |
| 商人房 | 商人按钮上播 slime impact VFX + 商人吐槽台词 + **+100 金** |
| 假商人事件房 | 对所有玩家逐个触发 `FakeMerchant.FoulPotionThrown` |

准入由 `PassesCustomUsabilityCheck` 控制（战斗中 / MerchantRoom / FakeMerchant 事件房三选一）。

### 6.3 假商人事件（FakeMerchant）——可战斗的商店房

- **进入条件**（`IsAllowed`）：Act ≥ 2、单人、所有玩家持有 ≥100 金或持有 FoulPotion；
- **库存**：`BeforeEventStarted` 从 `_inventoryRelics` 洗牌取 6 件建 `MerchantRelicEntry`——**复用真商店的 MerchantInventory/MerchantRelicEntry**，但只卖遗物；
- **掀桌**：扔 FoulPotion → `StartedFight = true` → `EnterCombatWithoutExitingEvent<FakeMerchantEventEncounter>`（战斗奖励 300 金）；
- **战后**：`FakeMerchantsRug`（假商人的毯子）+ 货架上**所有未售遗物**作为奖励一次性掉落——"买了不如打了"的设计闭环。

## 7. 表现层

### 7.1 对话系统（`MerchantDialogueSet`）

从 `merchant_room` 本地化表按 `MERCHANT.talk.<类别>` 前缀分组，8 类台词：

| 类别 | 触发 |
|---|---|
| `welcome` / `openInventory` | 进房间 / 开购物袋 |
| `purchaseSuccess` | 成交 |
| `purchaseFailureGold` / `Space` / `Forbidden` | 三种失败各有专属吐槽 |
| `foulPotion` | 被扔药水 |
| `playerDead` | 本地玩家已死仍逛商店 |

### 7.2 槽位 UI 与反馈

- 开/关购物袋：Tween（0.7s Quint 滑入 / 0.5s Cubic 滑出）+ Backstop 渐显；
- hover：槽位缩放 0.8（聚焦）/ 0.65（失焦），商人手 `NMerchantHand` 指向当前槽位，2s 后收回；
- 价格标签：金币不足染红、半价染绿；
- 购买失败：商品左右抖动 0.4s（`WiggleAnimation`，正弦 ±10px）；
- 手柄导航：横/纵两个方向手动织 `FocusNeighbor`，容器间按"最近的可见槽位"匹配（`GetClosestVisible`），商品售罄自动退出织网；
- FTUE：首次进商店弹 `NMerchantFtue`（`merchant_ftue` 存档标记）。

## 8. 历史记录与存档

- **看过**（未购买）：`MerchantRoom.Exit` 把所有 `IsStocked` 条目写入 `CurrentMapPointHistoryEntry`——卡牌进 `CardChoices`、遗物/药水进 `RelicChoices`/`PotionChoices`，全部 `wasPicked: false`；
- **买过**：购买瞬间按类型记 `BoughtColorless` / `BoughtRelics` / `BoughtPotions`（存 `PlayerMapPointHistoryEntry`）；
- **图鉴**：`SaveManager.MarkRelicAsSeen` / `MarkPotionAsSeen`（遗物/药水进店即标记"见过"，与购买解耦）。

双轨制的用途：战后统计展示"本层出现过/你买过什么"，以及图鉴收集进度。

## 9. 自研借鉴要点

1. **Entry 抽象 + 事件驱动**：条目自持价格与购买语义，UI 纯订阅；任一成交广播全库存重算，避免各处手动同步。
2. **价格三段式**（基础表 → 随机浮动 → Hook 修正）：折扣类道具作为 Hook 监听者接入，新增折扣遗物零商店代码改动。
3. **Cost 作为 getter 而非缓存**：修正管道天然覆盖"购买中途获得折扣遗物"的场景（本工程无此路径，但语义正确）。
4. **补货能力化**（`ShouldRefillMerchantEntry`）："无限补货商店"作为一个遗物词条实现，而非另写一个商店类型。
5. **库存去重双保险**：生成时排除已选 + 补货黑名单。
6. **服务价格递增 + 持久化计数**：删牌越用越贵，计数走存档字段。
7. **RNG 分流**：`PlayerRng.Shops` 专用流保证商店随机不影响战斗/奖励随机序列。
8. **"假商店"事件复用真库存类**：FakeMerchant 直接持 `MerchantInventory`，证明库存层与房间层解耦干净。
