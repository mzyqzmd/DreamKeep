### 发现的问题（用户尚未处理）
1. 工作区有**未提交重构改动**（`Action_*` → `IBA_*` 大量重命名 + 删除）→ 迁移前必须先 commit 或 stash 建锚点。
2. 根目录 20 个 csproj 中 **10 个不在 sln 内**：9 个对应 asmdef 已删（Application/Core/Composition/Domain/Simulation/Assembly-CSharp/NewAssembly/DOTween.Modules/EditModeTests），1 个是 `Presentation`（asmdef 有效但目录下无 .cs，Unity 对空程序集不生成 csproj —— 属正常行为，勿误判）。
3. 根目录污染：AI 会话留下的 `dk_compile.log`（51 KB）+ Windows 重定向误建的 `nul)`（24 B），建议删除（符合用户"不污染工作区"偏好）。
4. 无 `.editorconfig` → 建议补，锁 LF + `_camelCase` 私有字段等 README 已声明的规则。
5. 行尾三处不一致：`.gitattributes` eol=lf（优先生效）vs `core.autocrlf=true` vs Unity `m_LineEndingsForNewScripts: 0`(OS Native→CRLF)。不污染仓库，但建议把 Unity 改为 Unix(LF)。
6. README 架构章节漂移：写的是 `Core ← Domain ← Data ← Presentation` 四程序集，实际 asmdef 为 Utility/RuntimeData/Data/Gameplay/Presentation 五个。

### 迁移要点（易错项）
- Rider 必须 **File > Open 项目根目录**，不能双击 `.sln`（否则退化成普通 .NET 项目，Unity 集成面板消失）。
- 编译权永远在 Unity；Rider 内禁止 Build Solution / NuGet Restore（会生成 bin/obj 垃圾）。
- Unity `Preferences > External Tools > Editor Attaching` 必须勾选，否则断点不命中。
- csproj 生成范围必须含 **Git packages**，否则 UniTask / VContainer 无法跳转源码。
- 本项目 `m_EnterPlayModeOptionsEnabled: 0`（Domain Reload 开启）→ 手动点 Play 会中断调试会话，应使用 Rider 的 "Attach to Unity Editor & Play" 配置。
